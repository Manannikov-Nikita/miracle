# Кастомные графики через агента

Выберите результат на доске и опишите нужный график во встроенном чате. Агент подготовит SQL и композицию из SVG, HTML или Canvas. Можно попросить столбцы выше и ниже нуля, waterfall, выноски, стрелки, пояснения и локальные переключатели. Для изменения выберите тот же блок и напишите следующую команду.

Например:

> Сделай кастомный график из выбранного результата: столбцы выше и ниже нуля, цвет по этапу, выноски на 2030 и 2050, сноска с описанием данных. Добавь кнопку для скрытия подписей. Проверь привязку столбцов и состояние отрисовки.

График строится из сохранённого снимка SQL. Обновление результата перезапускает код на новых строках. Если SQL завершился ошибкой, прежний снимок сохраняется. В свойствах результата можно переключиться на таблицу и вернуться в «Кастомный график»: исходники остаются в блоке. SQL, размер, положение и удаление доступны обычными действиями доски. Выделяйте и перемещайте блок за рамку или заголовок; взаимодействия внутри графика принадлежат ему.

Текстовое описание поддерживается. Прикрепление изображения к чату и передача его CLI-провайдеру в эту возможность не входят.

## Как агент создаёт и меняет график

1. Прочитать `project_context`, текущую доску через `read_board` и контракт через `custom_chart_guide`. Идентификатор выбранного блока остаётся целью задания; исчезнувший блок нельзя заменять другим без указания пользователя.
2. Проверить подключение, схему, SQL и ограниченную выборку результата. Убедиться в именах, идентификаторах и типах столбцов. Подготовить снимок с нужной агрегацией.
3. Через `board_patch` создать или изменить результат: `kind: "result"`, `view: "custom"`, `source` с исходным SQL, `resultSetId` и `customChart`. Использовать текущую ревизию и UUID операции. При конфликте перечитать доску и применить изменение к актуальному документу.
4. Перечитать сохранённый блок. Большие исходники читать страницами, крупные изменения разбивать на отдельные операции в пределах лимитов запроса и всей доски.
5. На открытой доске запросить `read_custom_chart_status({ id, nodeId })`. Исправить обнаруженную ошибку ограниченным числом попыток. `not_observed` означает отсутствие свежего отчёта, а не успешную проверку. При закрытой доске сообщить, что код сохранён, но выполнение в браузере не наблюдалось.
6. Проверить внешний вид и взаимодействия в браузере. `rendered` подтверждает завершение синхронной инициализации, но не правильность геометрии, текста или визуальной композиции.

Отчёты привязаны к доске, блоку, снимку, хешу исходника и сессии браузера. Они действуют 60 секунд; открытый блок обновляет heartbeat. При нескольких вкладках итоговый статус учитывает свежие отчёты всех наблюдаемых сессий; подробности MCP выдаёт страницами по 10 записей (максимум 20) с `total` и `nextOffset`. Продолжайте чтение до `nextOffset: null`. Отчёты не содержат строки данных и исходники и не меняют ревизию доски. Запоздавший отчёт не может возобновить истёкшее наблюдение. При заполнении реестра новые сессии получают отказ; действующие отчёты сохраняются и продолжают обновляться.

Для интеграций: родительская страница при создании каждого отчёта фиксирует `sentAt` — целое безопасное число миллисекунд Unix — и сохраняет его вместе с `sequence` при повторе того же запроса. Сервер отклоняет отчёт возрастом 60 секунд и более и опережение времени более чем на 5 секунд. До 1 000 записей хранятся только в памяти. Видимость наблюдения истекает через 60 секунд после приёма; номер последовательности может оставаться ещё до 5 секунд для учёта допустимого опережения часов. Переполнение реестра возвращает HTTP 429 с кодом `CUSTOM_CHART_REPORT_CAPACITY`; оно не вытесняет действующую запись.

## Контракт версии 1

```ts
customChart: {
  version: 1,
  description: "Описание композиции, смысла данных и взаимодействий",
  html: '<div class="plot"></div>',
  css: '.plot { background: white; color: #142d33; }',
  javascript: '/* тело синхронной функции с аргументом api */'
}
```

Тело `javascript` получает:

```ts
{
  root: HTMLElement,
  columns: Array<{ id: string; name: string; type: string }>,
  rows: Cell[][],
  width: number,
  height: number,
  theme: "dark" | "light"
}
```

`Cell` сохраняет тип снимка, включая строки точных чисел, `null`, массивы и объекты. Не предполагайте фиксированный порядок столбцов: найдите индекс по проверенному ID или имени. Для обычного текста используйте `textContent`, для SVG — `createElementNS`. Значения из снимка нельзя вставлять как HTML или исполняемый код.

Пример привязки с явным выбором политики для чисел:

```js
const column = api.columns.findIndex(
  (c) => c.id === "volume" || c.name === "Объём",
);
if (column < 0) throw new Error("Нет столбца «Объём»");
const values = api.rows.map((row) => {
  const value = row[column];
  if (typeof value !== "number" || !Number.isFinite(value)) {
    throw new Error(
      "Ожидалось конечное число: проверьте тип или преобразование в SQL",
    );
  }
  return value;
});
const output = document.createElement("output");
output.textContent = values.length
  ? String(values.reduce((a, b) => a + b, 0))
  : "Нет строк";
api.root.append(output);
```

Это строгий пример: он намеренно отклоняет числовые строки. Если они нужны, выберите и объясните преобразование с проверкой диапазона и точности. Примеры ниже явно принимают конечные десятичные строки для приблизительной учебной геометрии, отвергают пропуски и числа за пределами `Number.MAX_SAFE_INTEGER`. Десятичная дробь при таком преобразовании может округляться; для точных денежных сумм подготовьте подходящую агрегацию и масштаб в SQL.

Инициализация синхронная; возврат Promise не поддерживается. Функция может вернуть очистку обработчиков, таймеров и других ресурсов. После инициализации допустимы асинхронные обработчики; глобальные ошибки и необработанные отклонения Promise попадут в диагностику. Локальные подсказки, наведение, клики, клавиатура и фильтрация доступны. SQL из кода графика не выполняется.

При смене кода, снимка, темы или размера блока среда запускается заново, временное состояние сбрасывается. Для композиции с фиксированными пропорциями используйте SVG `viewBox`; остальные варианты должны учитывать `api.width` и `api.height`. Масштабирование самой доски не меняет её логические размеры. Постоянные параметры храните в исходнике. Подписывайте основные элементы управления, обеспечивайте доступ с клавиатуры и заполняйте `description`.

## Два воспроизводимых примера

Исходники, строки, описания столбцов и SQL находятся в [tests/fixtures/custom-chart-examples.ts](../tests/fixtures/custom-chart-examples.ts). Файл предназначен для разработки и проверки; автоматического добавления примеров в пользовательскую доску нет. Оба примера работают без библиотек и сети. Все названия и числа вымышлены и помечены как синтетические.

| Экспорт                          | Композиция                                                                                                           | Данные и взаимодействия                                                                                                                                                               |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verticalColumnsExample`         | Положительные и отрицательные столбцы, три цветных этапа, числовые выноски на 2030 и 2050, стрелки, скобка и сноска. | Семь строк `year / value / phase`; высота и выноски вычисляются из значений снимка. Кнопка переключает подписи; Tab переводит фокус между столбцами и показывает текстовую подсказку. |
| `infrastructureWaterfallExample` | Горизонтальный waterfall, восемь категорий, соединители, итоговая полоса по группам и пояснение со сноской.          | Строки `category / amount / group`: 120, 80, 45, 60, 150, 75, 30, 440. Группы дают 305, 255 и 440, общий итог — 1 000. Кнопка переключает подписи, столбцы доступны по Tab.           |

Каждый экспорт содержит `{ id, title, spec, columns, rows, sql }`. `customChartExamples` объединяет оба. `sql` — запрос `SELECT … UNION ALL …` с литералами и именованными столбцами; снимок должен появиться через обычное выполнение SQL, а не через подмену реальных данных проекта. Все числовые значения графиков берутся из `api.rows`; исходник содержит оформление, вычисления и статические пояснения. Для пустого снимка выводится «Нет строк». Изменение строк меняет геометрию, значения выносок и суммы.

Проверки примеров запускают их через оболочку iframe в jsdom и проверяют поведение, включая перестановку столбцов и безопасную передачу строк. jsdom не заменяет проверку браузерного sandbox, CSP, размера и внешнего вида в настоящем браузере.

## Ограничения

| Объект                                                     | Предел                                                             |
| ---------------------------------------------------------- | ------------------------------------------------------------------ |
| Описание                                                   | 4 000 символов                                                     |
| HTML и CSS                                                 | по 100 000 символов                                                |
| JavaScript                                                 | 200 000 символов                                                   |
| Три исходника вместе                                       | 256 KiB в UTF-8                                                    |
| Доска с хотя бы одним `customChart`, даже в режиме таблицы | 1,5 MiB сериализованного документа в UTF-8                         |
| HTTP-запрос                                                | 2 MiB                                                              |
| Данные одного графика                                      | 5 000 строк, 100 000 ячеек, 5 MiB сериализованных `columns + rows` |

При превышении данных сервер отклоняет загрузку с предложением агрегировать SQL; молчаливого обрезания нет. Ограничение доски проверяется атомарно, в том числе после серии изменений агента. Ошибка `BOARD_TOO_LARGE` сохраняет предыдущий документ: сократите исходники или разделите доску.

Исходник выполняется в iframe с `sandbox="allow-scripts"` без доступа к origin приложения, его DOM, хранилищу и API. В него передаются только столбцы, строки, размеры и тема. SQL, идентификатор подключения, пути проекта и секреты в `api` не входят. Внешние библиотеки и CDN не поддерживаются; CSP запрещает внешние подресурсы и соединения. Ошибки загрузки и выполнения показываются в блоке вместе с повтором и переходом к таблице.

Обычный iframe не гарантирует отдельный процесс, квоту CPU или остановку бесконечного цикла. CSP не обеспечивает полный запрет самостоятельной навигации iframe и всех исходящих каналов. Неожиданная повторная загрузка прекращает обмен с блоком и переводит его в ошибку; это восстановление после навигации. Среда подходит для кода, который пользователь поручил агенту создать в локальном проекте, и не заявляет гарантированное исполнение заведомо враждебного JavaScript.

В первую версию не входят экспорт PNG/PDF/SVG, редактор JavaScript в интерфейсе, загрузка изображений в чат, внешние библиотеки, несколько независимых SQL-источников в одном блоке и сохранение временных фильтров между запусками. Исходники входят в обычный документ доски и его резервную копию.
