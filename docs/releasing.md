# Публикация Miracle

Готовящийся релиз 0.2.0 содержит приложение для macOS/Linux с Node.js и SQLite. Windows поддерживается через WSL 2 и те же Linux-архивы. Docker-образ и PostgreSQL не входят в пользовательскую установку.

## Подготовка

```sh
npm ci
npm test
npm run build
npm run notices
node scripts/build-release.mjs Manannikov-Nikita/miracle 0.2.0 .local/releases darwin-arm64
```

Параметры сборщика: repository, version, output, target и необязательный путь к заранее скачанному архиву Node. Четыре target: darwin-arm64, darwin-x64, linux-arm64, linux-x64. Используется фиксированный Node 24.22.2, архив runtime проверяется по SHA-256. Все четыре архива поставляются в `.tar.gz`; рядом с каждым публикуется файл `.sha256`.

Сборщик включает только compiled client/server, production-зависимости, runtime, launcher и лицензии. Рабочая директория целиком не архивируется. .local, базы, ключи, env и личные данные не должны попадать в payload.

## Проверка артефактов

Сборка исходников не подтверждает работу установщика. На нативных runners проверяются архивы каждой поддерживаемой платформы: запуск bundled runtime без системного Node, произвольный cwd, пробелы/Unicode в пути, start/status/stop, повторный запуск, занятый порт, установка/повторная установка, контрольные суммы и сохранность данных.

Отдельно проверяются SQLite-ключ, отказ второй копии, crash recovery, backup/restore в пустую область. Реальные ClickHouse/Trino и TLS интеграции запускаются с их тестовыми источниками.

Не называйте CI пройденным до фактического запуска workflow. Локальная macOS-проверка не заменяет Linux CI. Проверку сети WSL 2 и открытия адреса в браузере Windows фиксируйте отдельно: обычный Linux runner её не выполняет. Проверка на реальном WSL-хосте пока не выполнялась. Результаты фиксируются в [release-validation.md](release-validation.md).

## Публикация

После проверки исходников и артефактов создайте новый тег vX.Y.Z. Release workflow публикует четыре архива macOS/Linux, их SHA-256 и `install.sh` из того же выпуска. Версия внутри bootstrap-скрипта фиксирована, поэтому последующие скачивания относятся к одному тегу.

Не переназначайте опубликованный тег и не заменяйте его файлы другим содержимым. Для исправления нужен новый выпуск. Локальная сборка ничего не публикует.

Установщик `releases/latest/download/install.sh` доступен только после публикации этого asset. Пока 0.2.0 не опубликован, README обязан явно отмечать это; прежний выпуск 0.1.0 не содержит эти архивы и установщик.

После выпуска проверьте скачивание без авторизации, SHA-256 и чистую установку. Только затем уберите отметку «готовится к выпуску» и добавьте подтверждённые результаты проверки.
