# Публикация Miracle

Релиз 0.2.0 содержит native-приложение с Node.js и SQLite. Docker-образ и PostgreSQL не входят в пользовательскую установку.

## Подготовка

```sh
npm ci
npm test
npm run build
npm run notices
node scripts/build-release.mjs Manannikov-Nikita/miracle 0.2.0 .local/releases darwin-arm64
```

Параметры сборщика: repository, version, output, target и необязательный путь к заранее скачанному архиву Node. Target: darwin-arm64, darwin-x64, linux-arm64, linux-x64, win-x64. Используется фиксированный Node 24.22.2, архив runtime проверяется по SHA-256.

Сборщик включает только compiled client/server, production-зависимости, runtime, launcher и лицензии. Рабочая директория целиком не архивируется. .local, базы, ключи, env и личные данные не должны попадать в payload.

## Проверка артефактов

Сборка исходников не подтверждает работу установщика. На нативных runners проверяются архивы каждой поддерживаемой платформы: запуск bundled runtime без системного Node, произвольный cwd, пробелы/Unicode в пути, start/status/stop, повторный запуск, занятый порт, установка/повторная установка, контрольные суммы и сохранность данных.

Отдельно проверяются SQLite-ключ, отказ второй копии, crash recovery, backup/restore в пустую область. Реальные ClickHouse/Trino и TLS интеграции запускаются с их тестовыми источниками.

Не называйте CI пройденным до фактического запуска workflow. Локальная macOS-проверка не заменяет Windows/Linux. Результаты фиксируются в [release-validation.md](release-validation.md).

## Публикация

После проверки исходников и артефактов создайте новый тег vX.Y.Z. Release workflow публикует платформенные архивы, их SHA-256 и install.sh/install.ps1 из того же выпуска. Версия внутри bootstrap-скрипта фиксирована, поэтому последующие скачивания относятся к одному тегу.

Не переназначайте опубликованный тег и не заменяйте его файлы другим содержимым. Для исправления нужен новый выпуск. Локальная сборка ничего не публикует.

Установщики `releases/latest/download/install.sh` и `install.ps1` доступны только после публикации этих assets. Пока 0.2.0 не опубликован, README обязан явно отмечать это; прежний выпуск 0.1.0 не поддерживает native-установку.

После выпуска проверьте скачивание без авторизации, SHA-256 и чистую установку. Только затем уберите отметку «готовится к выпуску» и добавьте подтверждённые результаты проверки.
