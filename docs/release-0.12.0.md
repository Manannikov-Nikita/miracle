# Miracle 0.12.0 — DuckDB и датасеты проекта

В SQL-редакторе появился готовый источник **«Файлы и датасеты проекта»**. Он выполняет DuckDB SQL локально и доступен без настройки подключения к внешней базе.

## Сохранённые результаты

При добавлении таблицы на доску Miracle предлагает свободное SQL-имя. Оно уникально внутри проекта и независимо от заголовка блока. Сохранённый результат становится датасетом: его можно найти в проводнике, раскрыть столбцы и открыть новый запрос.

```sql
SELECT month, sum(revenue) AS revenue
FROM sales
GROUP BY month;
```

SQL читает все исходные сохранённые строки. Фильтры, скрытые столбцы, форматирование и преобразования на доске не меняют датасет. Результат нового запроса также можно сохранить на доску и использовать в следующих запросах.

Обновление выполняется явно. После успешного запроса связанные таблицы на разных досках получают новую версию данных, сохраняя своё оформление. Ошибка, отмена или пауза пакетного запроса оставляет прежние данные. Если схема перестала подходить графику или настройкам таблицы, блок показывает ошибку, позволяющую исправить представление. Уже выполняющийся запрос читает закреплённые версии входных датасетов; цепочки зависимостей автоматически не пересчитываются.

Действие «Редактировать исходный SQL» открывает запрос датасета. Кнопка «Обновить датасет по этому SQL» применяет изменения только вместе с успешным выполнением и проверкой ревизии. Обычная кнопка «Выполнить» запускает независимый запрос. Статус обновления и управление отменой или продолжением восстанавливаются после перезагрузки страницы.

Удаление блока или доски сохраняет датасет. Датасет можно удалить отдельно: SQL-имя исчезнет, а существующие блоки сохранят снимки данных. Переименование не переписывает сохранённый SQL. Старые таблицы работают без изменений; действие «Создать датасет» добавляет SQL-имя существующему результату.

## Файлы проекта

Поддерживаются CSV/TSV, Parquet, JSON/JSONL и XLSX. В дереве файлов действие «Запросить через DuckDB» создаёт SQL-вкладку с подходящей функцией чтения.

```sql
SELECT s.month, s.revenue, p.target
FROM sales AS s
JOIN read_csv('data/plan.csv') AS p USING (month);

SELECT *
FROM read_xlsx('data/plan.xlsx', sheet = 'Лист1');
```

Пути задаются строковыми литералами относительно корня проекта. Старые XLS, URL, glob-маски и вычисляемые пути не поддерживаются. Служебные каталоги и символические ссылки недоступны. Движок читает временные копии выбранных файлов; исходные файлы не изменяются. Excel входит в комплект и не требует загрузки расширения при первом запуске.

Поля `__proto__` сохраняются в `STRUCT` и вложенных типах. Для результата типа `VARIANT` с таким полем используйте `CAST(значение AS VARCHAR)`, чтобы сохранить точное текстовое представление.

## Лимиты и хранение

Существующие настройки ограничивают время, параллельность и размер возвращаемого результата; по умолчанию это 120 секунд, два выполнения, 50 000 строк и 20 МиБ на результат. Размер входного датасета не ограничен размером страницы или лимитом выходных строк. DuckDB получает бюджет памяти 512 МиБ; подготовленные файлы и временные данные одного запуска вместе ограничены 2 ГиБ. Превышение лимита возвращает ошибку, данные не усекаются.

Метаданные датасетов и сохранённые строки находятся в SQLite и входят в резервную копию проекта. DuckDB не создаёт второе постоянное хранилище. SQLite обновляется со схемы 8 до 9. Резервная копия сохраняет датасеты; исходные пользовательские файлы проекта нужно переносить вместе с проектом, если будущие обновления запросов должны их читать.

## Агент и API

`run_query` принимает `{ kind: 'local', sql, mutationId }`; внешние источники по-прежнему используют `connectionId`. Добавлены `list_datasets`, `read_dataset`, `register_dataset`, `rename_dataset`, `delete_dataset`, `refresh_dataset`. Обновление использует обычные статусы SQL, отмену и отслеживание в чате.

Версия подготовлена в отдельной ветке; публикация выполняется отдельно. Результаты проверок записаны в [отчёте 0.12.0](release-validation-0.12.0.md).
