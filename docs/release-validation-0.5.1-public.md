# Проверка Miracle 0.5.1

> Архивный отчёт: ниже описаны проверки и платформы только на дату этого выпуска. Текущие поддерживаемые платформы и установка — в [руководстве](local-installation.md), актуальные проверки — в [отчёте текущего выпуска](release-validation.md).

Изменения включены в `main` через [PR #4](https://github.com/Manannikov-Nikita/miracle/pull/4). Тег `v0.5.1` указывает на `8710443a84bda1af47bf44ce9ec1450ea3583ddb`.

[Miracle 0.5.1](https://github.com/Manannikov-Nikita/miracle/releases/tag/v0.5.1) опубликован **4 ноября 2026 года, 11:51:24 UTC**. В выпуск загружены четыре native-архива, четыре файла SHA-256 и `install.sh`. Публичная загрузка всех файлов и контрольные суммы проверены без авторизации; установка и обновления через официальный выпуск прошли на macOS ARM64.

## Локальные проверки

На Node.js **24.22.2** выполнены:

- `npm test`: **109 файлов, 1 339 тестов прошли**.
- `npm run build`: обе TypeScript-проверки и production-сборка прошли. Осталось предупреждение Vite о размере основного JS-бандла.
- `git diff --check`: без ошибок.
- `npm run test:integration`: **11 групп прошли** с реальными SQLite, ClickHouse 25.8 и Trino 484.
- `npx tsx tests/clickhouse-tls-integration.ts`: **6 групп прошли** с реальным ClickHouse HTTPS/mTLS, входом по сертификату, точными числовыми значениями, метаданными, таймаутом и проверками отказа.

Интеграции выполнены в отдельном Compose-проекте, с новым тестовым хранилищем и случайными localhost-портами. TLS-сценарий использовал одноразовый контейнер и синтетические сертификаты. Тестовые контейнеры, сеть и volume удалены; пользовательские сервисы и данные не менялись.

При приёмке исправлены две проверки инфраструктуры. Healthcheck Trino теперь дожидается `starting:false`: прежняя HTTP-проверка могла пропустить запросы до окончания запуска. Ожидание отказа ClickHouse проверяет структурированную диагностику `CONNECTION_HTTP`, код 164, имя `join_use_nulls` и `READONLY`; локализованное сообщение больше не влияет на тест. Оба исправления подтверждены повторными запусками.

## Интерфейс и браузер

Проверены создание доски без повторного заголовка, показ пароля, импорт JDBC и вход Trino через синтетический HTTPS/OAuth-сервер. В интерфейсе агента проверены вращение индикатора, расположение действий под ответом и доступность журнала. Автодополнение выходит за границы редактора, описание подстраивается под текст, а рекомендации `GROUP BY` и `ORDER BY` учитывают текущий SELECT.

Сценарии, скриншоты и ограничения находятся в [подробном отчёте 0.5.1](release-validation-0.5.1.md).

## Границы подтверждения

Корпоративный адрес и IdP пользователя в тестах не использовались. Синтетический HTTPS/OAuth-сервер подтверждает протокол, но не конкретное корпоративное развёртывание. Реальный Claude CLI, Windows-хост с WSL 2, fish и мобильный интерфейс не проверялись. Возможности установленного Codex CLI проверены без модельного запроса. Для команд без обязательного протокола структурированного чата нужен отдельный адаптер или терминальный режим.

SQL-анализатор работает с незавершённым текстом редактора; схемы CTE/derived tables не выводятся, а классификация неизвестных UDF без метаданных не гарантируется. Установочные проверки не подтверждают перенос браузерного localStorage; для старых SQL-черновиков нужен исходный origin.
