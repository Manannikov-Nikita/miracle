# Miracle 0.7.0 — первый набор изменений

Дата: 2026-11-05. Ветка `codex/release-0.7.0`, база `5df817a` (0.6.0). Версия пакета поднята до 0.7.0. Выпуск пока не опубликован: после демонстрации планируется продолжение работы над функциями.

## Реализовано

- Одиночный SQL показывает текущее и окончательное время выполнения, включая повторно открытые запуски.
- Запуск по датам показывает приблизительное оставшееся время по среднему времени завершённых дат. Паузы исключены; до первой измеренной даты отображается пояснение. Завершённые и остановленные серии не показывают прогноз. Дополнительные поля совместимы с прежним JSON, миграция не нужна.
- SQL-подсказки ищут подстроку без учёта регистра, с приоритетом совпадения в начале имени. Это распространяется и на составные агрегаты ClickHouse (`umIf` → `sumIf`, `OrNull`). Контекст SQL, диапазоны вставки и ограничения каталога сохранены.
- LaTeX `$…$` и `$$…$$` работает в Markdown-файлах, блоках доски, таблицах и сообщениях агента. Клик раскрывает исходник; код остаётся буквальным. KaTeX использует локальные CSS/шрифты, `trust: false` и ограничения расширений/размера.
- Заметки оформлены как жёлтые стикеры с центрированием. Размер текста подбирается по измеренным размерам в диапазоне 14–56 px; очень длинный текст остаётся доступен через прокрутку textarea.

## Проверки

- Node.js 24.22.2: `npm test -- --maxWorkers=4` — **128 файлов, 1589 тестов прошли**, включая последующие изменения заметок и чата агента.
- `npm run build` — обе проверки TypeScript и production-сборка прошли. Сохраняется предупреждение Vite о крупном JS bundle.
- Обновлены зависимости и `THIRD_PARTY_NOTICES.md`; проверка форматирования новых компонентов/помощников и `git diff --check` прошли.
- Независимое ревью проверило все четыре области. Ограничение генерации составных агрегатов исправлено, пять регрессий добавлены; оставшихся замечаний нет.
- Браузер: короткий текст 56 px, длиннее — 25 px; длинные слова и многострочный текст доходят до 14 px без горизонтального переполнения. Ввод в конце прокручивает к курсору; перетаскивание меняет подобранный размер, undo возвращает геометрию.
- Браузер: формулы отрисованы на доске; серия из восьми тестовых дат после первой даты показала около 20,8 с до окончания и завершилась с восемью строками. Проверены внутренние совпадения `ount`, приоритет `amount`, обновление после Backspace/дописывания и вставка `total_amount` через Enter в реальном Monaco.

Первоначальный запуск под системным Node 25 в ограниченной среде выявил `listen EPERM` и несовместимость экспериментального Web Storage с тестовым окружением. Повторение на разрешённых локальных портах подтвердило причины; финальная полная проверка выполнена под поставляемым Node 24.

## Локальная демонстрация

По просьбе пользователя все четыре сценария повторены в **@Browser**. Подтверждены финальные 2,4 с одиночного запроса, появление прогноза после первой даты, подсказки `ount`, приоритет `amount`, выбор `total_amount` стрелками и Enter, раскрытие LaTeX кликом и возврат к формуле при потере фокуса.

Этот браузер выявил обратную связь полосы прокрутки с переносом текста стикера: после уменьшения шрифта ранее появившийся scrollbar продолжал сужать поле на 7 px. Теперь прокрутка включается только когда текст не помещается даже при 14 px. Повторная проверка: образец при 22 px имеет одинаковые `scrollHeight` и `clientHeight` (187 px); 40 строк остаются прокручиваемыми при 14 px; короткий текст вновь получает 56 px. Итоговый снимок: `.local/release-0.7.0/screenshots/browser-demo.jpg`. Вкладка @Browser оставлена открытой как демо.

Настройки замены NULL объединены с нижней секцией «Подстановка значений». Убраны отдельное поле «Вместо NULL», чекбокс NULL и номера в подписях полей; номер остаётся в заголовке карточки. Цвет выбирается кружком рядом с заголовком. Новая подстановка получает исходное значение NULL; ввод текста, пустая строка и буквальный текст «NULL» различаются, кнопка внутри поля возвращает NULL. Старый `nullText` показывается последним правилом и сохраняет прежний приоритет; редактирование подстановок переносит его в общий список с учётом лимита 20 правил. Просмотр и изменение других настроек не переписывают сохранённые правила. В @Browser проверены создание, независимая замена NULL/текста/пустой строки, возврат к NULL и выбор цвета (отрисовка проверена в существующем режиме «Цвет текста»). Инспектор, модель, схема и таблица — 116 тестов — и production-сборка прошли. Снимок: `.local/release-0.7.0/screenshots/value-mappings-compact.jpg`; тестовая таблица: `.local/release-0.7.0/mapping-preview.html`.

В разделе «Данные → Форма таблицы» добавлены «В длинную · melt» и «В широкую · pivot» без агрегации; прежняя сводная доступна как «Сводная с расчётом». Melt переносит выбранные столбцы в пары ключ/значение, остальные остаются идентификаторами. Pivot поддерживает несколько ключей строк, сохраняет исходные значения и явно отклоняет повторные пересечения даже при одинаковых значениях. NULL, числовые строки высокой точности, логические и составные значения сохраняются без числового преобразования; смешанные типы melt получают безопасный тип Mixed. Преобразование выполняется над полным отфильтрованным снимком, затем применяются сортировка и оформление. Действуют лимиты в 1 000 000 выходных ячеек и 200 столбцов значений pivot.

Проверка melt/pivot: полный набор **130 файлов, 1656 тестов прошёл**; после найденной в Browser скрытой подсказки конфликта добавлена отдельная регрессия, все **19 тестов TableView прошли**, повторная production-сборка прошла. Независимое ревью модели не нашло ошибок; замечание интеграционного ревью о потере оформления при переименовании исправлено и проверено регрессионным тестом. В @Browser показаны преобразования 3 широких строк в 6 длинных и обратно с двумя ключами, сохранение NULL, конфликт при недостаточном наборе ключей и восстановление после добавления ключа. Демо `.local/release-0.7.0/reshape-preview.html`; снимки `table-melt.jpg`, `table-pivot.jpg`, `table-pivot-conflict.jpg` в `.local/release-0.7.0/screenshots/`. Локальный сервер демо перезапущен с обновлённой схемой; существующие пользовательские файлы сохраняются.


Преобразования таблицы теперь используются обычными и кастомными графиками того же блока: фильтры, сортировка, скрытие/порядок/названия столбцов, агрегирующая сводная, melt и pivot без агрегации. Заголовочная сортировка редактируемой таблицы сохраняется и переходит в график. Обычные графики получают подстановки, числовое оформление и активные цвета ячеек в подписи/подсказки; числовые координаты остаются исходными и проходят прежние проверки точности. Кастомный API получает преобразованные raw rows и отдельные displayRows/cellColors для оформления. Тики общей числовой оси сохраняют формат графика. Ширина, перенос, плотность и итоговый футер таблицы не создают дополнительные точки. Независимые копии блока сохраняют независимые настройки.

Для кастомных графиков добавлен совместимый POST-эндпоинт с TableSpec; прежний GET остаётся доступным. Общая чистая модель таблицы перенесена в shared, а decimal.js — в runtime dependencies для релизной установки. Лимиты исходного снимка остаются 50 000 строк / 20 MiB / 1 000 000 ячеек; лимиты обычного графика и кастомного payload проверяются после преобразования. Диагностическая идентичность учитывает настройки таблицы. Конфликты pivot видны сразу в обоих видах графиков; пустой фильтр показывает пустое состояние. Melt разных числовых SQL-типов сохраняет точные raw значения и числовую метаинформацию.

Финально: **132 файла / 1684 теста прошли**, `npm run build` прошёл на Node 24.22.2; только прежнее предупреждение Vite о крупном bundle. В @Browser проверены живые компоненты с локальным снимком: фильтр 3→2 строки, переименование, подстановка города, суффикс «шт.», сортировка заголовком, melt 3→6 строк, pivot 6→3, новые поля осей, обновление кастомного iframe и конфликт при удалении ключа. API/лимиты/диагностика дополнительно проверены серверными тестами. Основное демо перезапущено с новым сервером и проверено после загрузки.
