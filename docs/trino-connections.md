# Подключение Trino: пароль, браузерный вход и корпоративный CA

Откройте **Подключения → Новое подключение → Trino** или настройки сохранённого Trino-подключения. Miracle обращается к Trino из локального сервиса, поэтому адрес должен быть доступен с компьютера, где он запущен.

## Настройка в приложении

1. Укажите HTTPS-адрес координатора или шлюза Trino, пользователя, пароль при необходимости, каталог и схему. Порт зависит от настройки вашего Trino; переключатель **Использовать HTTPS** сохраняет нестандартный порт и путь.
2. По умолчанию Miracle автоматически использует доверенные сертификаты Node.js и операционной системы. Если корпоративный CA отсутствует в системном хранилище, в разделе **SSL / TLS → Корневой сертификат CA** нажмите **Указать CA вручную** и выберите доверенную цепочку. Нужен текстовый PEM в UTF-8, до 128 КиБ; расширение может быть `.pem`, `.crt` или `.cer`. DER, PFX/P12 и закрытые ключи в этом поле не принимаются.
3. Нажмите **Проверить**. Проверка использует выбранный CA и текущие поля формы, выполняет `SELECT version()` и не сохраняет изменения.
4. После успешной проверки нажмите **Сохранить подключение**.

Сертификат сервера и соответствие его имени адресу проверяются всегда. Укажите имя хоста из сертификата, а не IP-адрес, если сертификат не содержит этот IP. Для сертификата публичного центра файл CA обычно не нужен. Этот раздел поддерживает доверие корпоративному CA; клиентская аутентификация mTLS для Trino здесь не настраивается.

Выбранный CA действует только для этого подключения и используется при проверке, интроспекции, выполнении запросов, чтении следующих страниц результата и отмене. Он не добавляется в доверенные сертификаты других подключений. Если CA выбран явно, доверие определяется этой цепочкой; при ошибке нет скрытого возврата к системному доверию. Удаление ручного CA возвращает автоматический режим.

CA хранится зашифрованно в SQLite вместе с настройками подключения. Он переживает перезапуск и обновление приложения; обычная парная резервная копия SQLite и ключа включает его. При повторном открытии формы видно **Сохранён**, но содержимое сертификата обратно в браузер не отправляется. Чтобы сохранить текущий CA, оставьте поле без изменений; для замены выберите новый файл, для удаления нажмите корзину. Переключение на HTTP требует явного удаления CA.

## Импорт JDBC и вход через браузер

Начиная с кандидата 0.5.1 форма импортирует адреса такого вида:

```text
jdbc:trino://trino.example:443?SSL=true&SSLVerification=FULL&externalAuthentication=true&externalAuthenticationTokenCache=MEMORY
```

Импорт извлекает HTTPS-адрес, каталог/схему из пути, параметры `user`/`password` и режим внешней авторизации. В сохранённом адресе нет JDBC-префикса или строки параметров. Поддерживается только `SSLVerification=FULL` и хранение токена `MEMORY`; неизвестные параметры вызывают ошибку. Файл корпоративного CA выбирается отдельно в форме. Java и JDBC-драйвер для этого не нужны: Miracle использует HTTP-протокол Trino.

Для кластера с OAuth/SSO выберите внешнюю авторизацию и запустите вход через браузер. Откройте предложенную ссылку, войдите у корпоративного провайдера и вернитесь в Miracle. После завершения входа проверьте подключение и сохраните его. Имя пользователя можно оставить пустым, чтобы Trino использовал пользователя из токена; если администратор требует явное имя, укажите его.

Ожидание входа можно отменить. Изменение полей и закрытие формы отменяют ожидающий вход; незавершённая сессия ограничена пятью минутами. Полученный токен остаётся только в памяти процесса и используется для запросов, метаданных и отмены. После перезапуска Miracle или отказа токена нужно войти снова. Токены не возвращаются в браузер и не входят в резервную копию; сохранённые подключения изолированы друг от друга, даже при одинаковом адресе.

Ссылка входа может вести к отдельному HTTPS-провайдеру. Адрес получения токена должен находиться на том же HTTPS-origin, что и координатор Trino; нестандартная схема с отдельным token server здесь не поддерживается. Miracle не передаёт пароль или Bearer-токен по ссылке входа либо при опросе token server.

Кнопка показа пароля раскрывает только текст, введённый в текущей форме. При редактировании сохранённый пароль остаётся на сервере; пустое поле сохраняет его прежнее значение.

Параметры и протокол описаны в [документации JDBC Trino](https://trino.io/docs/current/client/jdbc.html) и [реализации внешней авторизации клиента Trino](https://github.com/trinodb/trino/tree/master/client/trino-client/src/main/java/io/trino/client/auth/external).

## Альтернатива: дополнительный CA при запуске

Miracle автоматически объединяет стандартные CA Node.js и доверенные CA системы для подключений Trino и ClickHouse. Сертификат, установленный только в отдельном хранилище браузера, может быть недоступен системе. Дополнительные CA также можно передать через `NODE_EXTRA_CA_CERTS`:

```sh
~/.local/bin/miracle stop
NODE_EXTRA_CA_CERTS="$HOME/certificates/corporate-ca-chain.pem" ~/.local/bin/miracle
```

Замените путь на существующий файл с доверенной цепочкой. Переменная читается при старте Node.js: изменение окружения не влияет на уже работающий сервис. Задавайте её при каждом полном запуске, если используете этот способ. Править сгенерированный launcher `~/.local/bin/miracle` не нужно: установщик пересоздаёт его при обновлении. Для постоянной настройки отдельного источника используйте поле CA в форме.

`NODE_EXTRA_CA_CERTS` расширяет стандартное доверие всех соединений процесса, у которых CA не задан явно. Для подключений Miracle отдельный флаг `NODE_USE_SYSTEM_CA` не требуется. После изменения системного хранилища CA перезапустите Miracle: Node.js кэширует сертификаты. В WSL используется хранилище Linux; установленный в Windows сертификат сам по себе не становится доверенным внутри WSL. См. [NODE_EXTRA_CA_CERTS](https://nodejs.org/api/cli.html#node_extra_ca_certsfile).

## Если подключение не проходит

При ошибке доверия проверьте, что выбран правильный CA и сервер отдаёт необходимые промежуточные сертификаты. Ошибка имени требует проверить адрес Trino, ошибка срока действия — сертификат и часы компьютера. Ошибки DNS, недоступного порта и аутентификации не исправляются загрузкой CA.

**Недопустимый Origin** — отдельная проверка адреса локального интерфейса, выполняемая до обращения к Trino. Откройте приложение через `miracle open` и используйте напечатанный адрес без замены имени хоста, протокола или порта.
