# Защищённое подключение к ClickHouse

Администратор настраивает источник в **Подключения → Новое подключение** или открывает настройки существующего. Miracle подключается к HTTP-интерфейсу ClickHouse с сервера приложения, поэтому адрес и порт должны быть доступны именно ему.

## HTTPS и сертификаты

Укажите, например, `https://clickhouse.company.ru:8443` либо включите **SSL / TLS**. Переключатель меняет стандартный HTTP-порт 8123 на HTTPS-порт 8443; нестандартный порт сохраняется. HTTPS должен быть включён на стороне ClickHouse. Порты 9000/9440 относятся к нативному протоколу и для этого коннектора не подходят. См. [HTTP-интерфейс ClickHouse](https://clickhouse.com/docs/interfaces/http).

Сертификат сервера и его имя проверяются всегда. Для сертификата публичного центра сертификации дополнительные файлы обычно не нужны. Для внутреннего центра загрузите **CA-сертификат** в PEM: поддерживается один сертификат или цепочка. Можно использовать расширения `.pem`, `.crt`, `.cer`, но содержимое должно быть текстовым PEM. DER и PFX/P12 не поддерживаются.

Если сервер или TLS-прокси требует взаимную аутентификацию (mTLS), выберите **сертификат клиента** и соответствующий **закрытый ключ** в PEM. Ключ должен быть без парольного шифрования. Ограничение — 128 KiB на каждый файл. Miracle проверяет формат и соответствие ключа сертификату до сохранения.

По умолчанию клиентская пара используется для TLS-соединения, а пользователь ClickHouse входит по логину и паролю. Если в ClickHouse настроен пользователь с аутентификацией по сертификату, включите **Вход в ClickHouse по сертификату** и укажите его имя. В этом режиме пароль не отправляется. Требуется соответствующая настройка пользователя и доверия на самом сервере; загрузка сертификата в Miracle её не заменяет. См. [аутентификацию по SSL-сертификату](https://clickhouse.com/docs/guides/sre/ssl-user-auth).

Содержимое сертификатов и ключа хранится в SQLite зашифрованно ключом Miracle, как пароль подключения. При повторном открытии формы отображается только наличие сохранённых файлов. Оставьте их без изменений для сохранения, выберите новый файл для замены или явно удалите. Секреты не возвращаются браузеру и не записываются в черновики. Резервная копия требует сохранения БД вместе с исходным ключом шифрования.

## Параметры

**Таймаут HTTP-запроса** задаётся в секундах (1–600; по умолчанию 120) и действует на весь запрос, включая чтение ответа. Он не увеличивает общий лимит выполнения в Miracle. Проверка подключения и метаданные также ограничены собственным временем ожидания.

**Сжатие** включает gzip для запроса и ответа. Лимиты результата проверяются после распаковки. Для ответа ClickHouse должен разрешать настройку `enable_http_compression`.

В форме доступны следующие настройки запроса:

| Параметр                             | Назначение                                      |
| ------------------------------------ | ----------------------------------------------- |
| `max_threads`                        | Максимальное число потоков                      |
| `max_memory_usage`                   | Лимит памяти запроса в байтах                   |
| `max_bytes_before_external_group_by` | Порог сброса агрегации на диск; 0 отключает     |
| `max_bytes_before_external_sort`     | Порог сброса сортировки на диск; 0 отключает    |
| `join_use_nulls`                     | Использование NULL при отсутствии строки в JOIN |
| `session_timezone`                   | Часовой пояс сессии, например `Europe/Moscow`   |

Права пользователя и ограничения профиля ClickHouse действуют независимо от формы. Для пользователя с `readonly=1` изменяемые параметры нужно явно разрешить администратору ClickHouse через `changeable_in_readonly`. Локальный стандартный профиль Miracle разрешает только параметры, необходимые самому приложению. Дополнительные параметры могут быть отклонены сервером — Miracle покажет ошибку.

Параметры URL, произвольные HTTP-заголовки, изменение формата ответа и отключение проверки TLS не поддерживаются. Формат данных и ограничения результата устанавливает сервер Miracle. Доступ только на чтение обеспечивается правами технического пользователя ClickHouse.

## Проверка

Кнопка **Проверить** в форме выполняет `SELECT version()` с текущими полями, включая выбранные файлы. При редактировании используются сохранённые секреты, если они не заменены или явно не удалены. Проверка не сохраняет изменения. После успеха сохраните подключение отдельной кнопкой.

Для проверки реализации с настоящим ClickHouse 25.8 и временными CA/client/server-сертификатами:

```sh
npx tsx tests/clickhouse-tls-integration.ts
```

Тест создаёт отдельный Docker-контейнер с HTTPS/mTLS и удаляет его по завершении. Постоянные контейнеры и данные Miracle не меняются.
