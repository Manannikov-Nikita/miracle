# Установка Miracle на свой компьютер

[← Обзор](../README.md) · [Руководство](usage.md)

Miracle — локальный сервис для одного человека. Готовая сборка содержит runtime; PostgreSQL, Docker, Node.js, npm и Git устанавливать не нужно. Codex CLI и Claude CLI для работы агентов устанавливаются отдельно.

Проекты и агенты, описанные ниже, относятся к текущей исходной версии и ещё не опубликованы в релизе 0.2.1. В опубликованной 0.2.1 данные находятся в общем каталоге установки `data/`, порт по умолчанию — 3001. При переходе используйте [инструкцию переноса](#перенос-существующей-рабочей-области).

## macOS и Linux

Нужны браузер, curl и стандартные средства распаковки/проверки SHA-256. Сборки: macOS Intel/Apple Silicon и GNU/Linux x64/ARM64. Alpine/musl не поддерживается. Используйте архив, контрольную сумму и установщик из одного [GitHub Release](https://github.com/Manannikov-Nikita/miracle/releases).

```sh
curl -fsSL https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh | sh
```

Установка выполняется в домашний каталог без sudo. Если команда ещё не найдена в PATH, используйте `~/.local/bin/miracle` и следуйте подсказке установщика. Скрипт можно сначала скачать и прочитать:

```sh
curl -fL -o install.sh https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh
sh install.sh
```

## Windows через WSL 2

Нужен WSL 2 с дистрибутивом GNU/Linux x64 или ARM64, например Ubuntu: [установка WSL](https://learn.microsoft.com/en-us/windows/wsl/install). Команды установки и все команды `miracle` выполняйте в терминале этого дистрибутива. Установщик выберет Linux-архив по архитектуре WSL.

Держите программу и проекты в домашнем каталоге Linux, например `~/projects/analysis`, а не в `/mnt/c`. Для `MIRACLE_INSTALL_ROOT` и `--data-dir` также выбирайте Linux-пути: [рекомендация Microsoft](https://learn.microsoft.com/en-us/windows/wsl/filesystems).

Откройте напечатанный Miracle адрес в браузере Windows: [сеть WSL](https://learn.microsoft.com/en-us/windows/wsl/networking). Используйте адрес точно как напечатано; Miracle проверяет Host и Origin. Команда не требует Linux-браузера. Нативная установка Windows не поддерживается.

## Проект и первый запуск

Запускайте Miracle из папки своего проекта:

```sh
mkdir -p ~/projects/analysis
cd ~/projects/analysis
~/.local/bin/miracle
```

Текущая папка становится проектом. Данные Miracle сохраняются в её `.miracle/`: подключения, сохранённые SQL, документы редактора, снимки, доски, профили агентов и чаты. Обычные файлы проекта остаются рядом с этой папкой. Добавьте `.miracle/` в `.gitignore`: в ней находятся база и ключ шифрования.

`miracle` или `miracle open` запускает сервис в фоне и печатает адрес `http://127.0.0.1:PORT`; свободный порт выбирает ОС. На macOS/Linux команда также открывает браузер; в WSL перейдите по адресу вручную. Аккаунт Miracle не нужен: добавьте источник в «Подключениях».

Повторный запуск для той же папки, включая путь через символическую ссылку, открывает работающий экземпляр. Разные проекты имеют отдельные процессы, порты и браузерные сессии. Для запуска из другого места задайте проект явно:

```sh
miracle open --project-dir ~/projects/analysis
miracle status --project-dir ~/projects/analysis
```

| Команда                        | Действие для выбранного проекта                 |
| ------------------------------ | ----------------------------------------------- |
| miracle / miracle open         | Запустить и открыть браузер                     |
| miracle start                  | Запустить в фоне                                |
| miracle stop                   | Остановить сервис, активные SQL и задачу агента |
| miracle status / status --json | Проверить состояние и фактический адрес         |
| miracle serve                  | Запустить в текущем терминале                   |
| miracle --help / --version     | Справка / версия                                |

`--port 3002` или `PORT=3002` задаёт конкретный порт. Если он занят, запуск завершится ошибкой. Для смены порта работающего проекта сначала выполните `miracle stop`. На один каталог данных допускается только один процесс.

`--data-dir PATH` или `MIRACLE_DATA_DIR` меняет только место хранения; папкой проекта и рабочим каталогом агента остаётся текущая папка либо `--project-dir`. Повторяйте переопределение для `status`, `stop`, `backup` и `restore`. Другой проект не может присвоить себе каталог данных зарегистрированного экземпляра. Для одной папки проекта работает один сервис даже при разных `--data-dir`: перед сменой хранения остановите текущий экземпляр с его прежним `--data-dir`. Команды с несовпадающим каталогом данных, включая `status` и `stop`, сообщат о работающем экземпляре и потребуют указать его хранение.

Для корпоративного HTTPS загрузите PEM CA в настройках источника. Подробности: [Trino](trino-connections.md), [ClickHouse и mTLS](clickhouse-connections.md). Источник в той же среде доступен через `127.0.0.1` и свой порт. В WSL это Linux-среда; доступ к источнику Windows зависит от [режима сети WSL](https://learn.microsoft.com/en-us/windows/wsl/networking). Демонстрационные серверы не устанавливаются.

## Файлы программы и данные

| ОС                   | Глобальный каталог установки             |
| -------------------- | ---------------------------------------- |
| macOS                | ~/Library/Application Support/Miracle    |
| Linux, включая WSL 2 | ${XDG_DATA_HOME:-~/.local/share}/miracle |

Код находится в `versions/`. Приватный реестр экземпляров — в `run/`, отдельные журналы проектов — в `logs/`. Эти каталоги общие для установки; данные каждого проекта по умолчанию лежат в `PROJECT/.miracle/`. Старый общий `data/` автоматически не переносится.

В каталоге данных находятся `miracle.sqlite` и `encryption.key`. Ключ создаётся один раз. При потере или подмене ключа существующая база не переинициализируется: восстановите исходную пару из копии.

## Резервное копирование и восстановление

Команды работают с текущим проектом или `--project-dir`:

```sh
cd ~/projects/analysis
miracle stop
miracle backup ../analysis-backup
miracle start
```

Копия содержит согласованный снимок SQLite, ключ и манифест. В неё входят документы редактора, доски, результаты, профили и чаты. Обычные файлы проекта и домашние настройки/авторизация Codex или Claude не входят. Храните копию приватно: ключ позволяет расшифровать пароли источников и команды профилей.

Восстановление в новый проект с отсутствующей либо пустой `.miracle/`:

```sh
mkdir -p ~/projects/restored-analysis
miracle restore ~/projects/analysis-backup --project-dir ~/projects/restored-analysis
miracle open --project-dir ~/projects/restored-analysis
```

Непустой каталог не перезаписывается. Не копируйте один SQLite-файл работающего сервиса: часть данных может находиться в WAL. После переноса проверьте исполняемые команды профилей и подтвердите их локально перед запуском агента; разрешение запуска не переносится с копией.

## Перенос существующей рабочей области

SQL-черновики предыдущих версий хранятся в браузере по исходному origin: протоколу, адресу и порту. Остановите прежний сервис его текущей командой `miracle stop`, повторив прежний `--data-dir`, если он был задан. Затем откройте старые данные новой исходной сборкой на **том же адресе и порту**, используя тот же браузер и профиль. Например, для старого адреса `http://127.0.0.1:3001` на macOS:

```sh
miracle open --data-dir "$HOME/Library/Application Support/Miracle/data" --port 3001
```

На Linux/WSL прежний каталог обычно `${XDG_DATA_HOME:-$HOME/.local/share}/miracle/data`. Дождитесь загрузки и импорта SQL-вкладок в серверные документы; проверьте их текст. Переход сразу на новый свободный порт не даёт браузеру доступа к черновикам старого origin. При сомнениях скачайте важные `.sql` отдельно до переноса.

Затем остановите этот экземпляр и перенесите данные через копию:

```sh
miracle stop --data-dir "$HOME/Library/Application Support/Miracle/data"
miracle backup ~/miracle-old-backup --data-dir "$HOME/Library/Application Support/Miracle/data"
mkdir -p ~/projects/analysis
miracle restore ~/miracle-old-backup --project-dir ~/projects/analysis
miracle open --project-dir ~/projects/analysis
```

Сохраняйте старый каталог и копию до проверки нового проекта. PostgreSQL-данные версии 0.1.0 автоматически не импортируются и не удаляются.

## Обновление и удаление

Перед обновлением сделайте копии нужных остановленных проектов и повторите установку. Новый установщик аутентифицирует и корректно останавливает все зарегистрированные экземпляры перед активацией кода. При невозможности проверить экземпляр он прекращает обновление. Исчезнувший каталог данных не создаётся заново ради проверки.

Старые версии программы не заменяют копию данных. Не открывайте более новую схему старой версией приложения. Для удаления сначала остановите проекты; удаление кода установки не удаляет их `.miracle/`. Удаление папки проекта вместе с `.miracle/` удаляет его данные. Сохраняйте копии вне удаляемых папок.

Для offline установки скачайте `.tar.gz`, соседний `.sha256` и `install.sh` из одного релиза; задайте `MIRACLE_ARCHIVE` равным пути к архиву. `MIRACLE_INSTALL_ROOT` и `MIRACLE_BIN_DIR` задают каталоги установки и launcher; сохраняйте их при последующих обновлениях.
