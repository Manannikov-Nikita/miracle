# Miracle — локальная рабочая область

Нужны работающий Docker и браузер. Node.js, Git и компиляторы не нужны. Установка доступна только на этом компьютере; источники ClickHouse и Trino подключаются самостоятельно. Демонстрационных серверов и данных в комплекте нет.

## Установка

1. Установите [Docker Desktop](https://docs.docker.com/get-docker/) для Windows/macOS или Docker Engine с плагином Compose v2 для Linux. Запустите Docker. На Windows используйте Linux containers / WSL 2.
2. Скачайте **miracle-X.Y.Z.zip** из Releases репозитория, распакуйте целиком. Не выбирайте GitHub «Source code (zip)»: это исходники для разработчиков.
3. Запустите:

| Система | Действие |
| --- | --- |
| Windows 11 x64 | Двойной клик по `start.cmd` |
| macOS Intel / Apple Silicon | В Терминале перейдите в распакованную папку и выполните `sh start.sh` |
| Linux x64 / ARM64 | В терминале перейдите в распакованную папку и выполните `sh start.sh` |

Пробелы и кириллица в пути допустимы. Не запускайте скрипты через `sudo`, если Docker уже доступен обычному пользователю. Windows ARM пока экспериментален. Скрипты используют Compose v2 с поддержкой `up --wait`; при ошибке обновите Docker.

Первый запуск скачивает готовые образы. Браузер откроется автоматически; если этого не произошло, скопируйте строку **Open Miracle** из терминала. Обычный адрес — **http://localhost:3001**. Для первого входа используется адрес с одноразовым фрагментом `#setup=…`: не передавайте эту ссылку другим людям.

В мастере укажите имя, email и пароль от 12 символов. Откроется пустая среда: нажмите **«Подключить источник»**. Ссылка действует 30 минут. Если она истекла, снова запустите `start` и откройте новую ссылку. Новая ссылка отменяет предыдущую. После создания администратора мастер закрывается; последующие запуски открывают обычный вход.

## Первый запрос

Выберите ClickHouse или Trino и заполните параметры доступа. Для ClickHouse поддерживаются HTTPS, порт 8443, собственный CA, клиентский сертификат и ключ. Пароли и ключи подключений хранятся зашифрованными.

Если СУБД работает **на этом же компьютере**, вместо `localhost` в подключении используйте **host.docker.internal**, например `http://host.docker.internal:8123`. Эта настройка предусмотрена и для Linux. СУБД должна принимать подключения от Docker; проверьте её интерфейс прослушивания и firewall. `localhost` внутри контейнера означает сам контейнер Miracle.

Используйте технического пользователя СУБД с правами чтения. После подключения выберите базу или каталог/схему, напишите SELECT и нажмите **Ctrl/Cmd+Enter**. Результат можно добавить на доску и превратить в график. Данные сохраняются между перезапусками.

## Участники

Администратор открывает иконку команды слева → **«Добавить участника»**, задаёт имя, email и роль. Miracle создаёт одноразовую ссылку на 24 часа; её нужно передать самостоятельно. Получатель задаёт пароль. В этой локальной поставке ссылка открывается только **на том же компьютере**. Общедоступная регистрация и отправка email не предусмотрены.

## Порт и остановка

Если 3001 занят, измените одну строку в **settings.env**, например `MIRACLE_PORT=3002`, затем снова запустите `start`. Адрес приложения и ссылки будут использовать новый порт. Не меняйте адрес на внешний интерфейс: комплект рассчитан на loopback.

Остановка: **stop.cmd** в Windows или **sh stop.sh** в macOS/Linux. Повторный запуск: `start`. Данные и секреты остаются в Docker volumes проекта **miracle-local**. Переименование или перемещение папки установки не создаёт другую рабочую область. Две распакованные копии на одном компьютере обращаются к одной установке.

**Не удаляйте volumes и не используйте `docker compose down -v`: это удаляет рабочую область.** Очистка Docker Desktop с удалением volumes также удаляет данные. Удаление одной распакованной папки не удаляет volumes.

## Резервная копия, перенос и обновление

Все инструменты PostgreSQL запускаются внутри Docker.

| Действие | Windows | macOS / Linux |
| --- | --- | --- |
| Копия | `backup.cmd` | `sh backup.sh` |
| Копия с выбранным путём | `backup.cmd "D:\Backup\miracle.tar.gz"` | `sh backup.sh "/путь/копия.tar.gz"` |
| Восстановление | `restore.cmd "D:\Backup\miracle.tar.gz"` | `sh restore.sh "/путь/копия.tar.gz"` |

Копия содержит PostgreSQL, пароль БД и соответствующий ключ шифрования. Она сохраняется рядом со скриптами, если путь не задан. Храните архив приватно и отдельно от компьютера. После копирования приложение остаётся остановленным, чтобы можно было обновить его без новых записей. Для обычного продолжения работы снова запустите `start`.

**Перенос:** скопируйте архив на новый компьютер, установите Docker, распакуйте комплект той же версии и запустите `restore` **до первого `start`**. Восстановление разрешено только в пустые volumes; существующая рабочая область не перезаписывается. Затем откройте обычный адрес и войдите прежними данными. Черновики SQL, хранящиеся в браузере, в серверную копию не входят: перед переносом сохраните их как общие запросы или скачайте `.sql`.

**Обновление:**

1. В папке текущей версии выполните `backup` и сохраните архив.
2. Скачайте и распакуйте выбранную новую версию. При изменённом порте перенесите `settings.env`.
3. Не запускайте старую версию после копирования; запустите `start` новой версии.
4. Дождитесь проверки здоровья, войдите и проверьте сохранённые доски.

Скрипт требует свежую копию перед сменой версии и отказывается от downgrade. Если обновление не удалось, данные не сбрасываются. Для возврата к старой версии восстановите её копию на чистой установке. Не удаляйте текущие volumes ради обхода ошибки.

## Если запуск не удался

- **Docker not found / unavailable:** установите или запустите Docker; Linux-пользователь должен иметь доступ к Docker daemon.
- **Port is already allocated / address already in use:** поменяйте `MIRACLE_PORT` в `settings.env` или освободите порт.
- **Could not download release images:** проверьте интернет и доступ к GHCR/Docker Hub, затем повторите запуск. Логин в GHCR не нужен; если образ требует логин, релиз опубликован неверно — сообщите автору.
- **Missing credentials / key verification failed:** не создавайте новый ключ. Восстановите соответствующую копию БД и секретов. Подробности: `docker compose logs --tail 80 app postgres`.
- **Another Miracle server / lock:** другая копия приложения уже использует ту же БД. Остановите лишний процесс; запуск не прерывает его SQL-запросы.
- **Incomplete restore:** автоматический запуск остановлен, чтобы не создать пустую среду вместо копии. Сохраните исходный архив; диагностика — `docker compose logs --tail 80`.

Ключ и пароль БД генерируются только при первой установке. PostgreSQL не публикует порт на компьютер. Незавершённые SQL-запуски после перезапуска помечаются прерванными, повторного выполнения не происходит.
