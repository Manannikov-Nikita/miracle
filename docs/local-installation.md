# Установка Miracle на свой компьютер

[← Обзор](../README.md) · [Руководство](usage.md)

Miracle — локальный сервис для одного человека. Готовая сборка содержит runtime; PostgreSQL, Docker, Node.js, npm и Git устанавливать не нужно.

Эта инструкция относится к версиям 0.2.x. Используйте установщик и архивы из одного [GitHub Release](https://github.com/Manannikov-Nikita/miracle/releases). Docker-комплект 0.1.0 этих файлов не содержит.

## macOS и Linux

Нужны браузер, curl и стандартные средства распаковки/проверки SHA-256. Сборки: macOS Intel/Apple Silicon и GNU/Linux x64/ARM64. Alpine/musl не поддерживается.

```sh
curl -fsSL https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh | sh
~/.local/bin/miracle
```

Установка выполняется в домашний каталог без sudo. Если команда ещё не найдена в PATH, используйте `~/.local/bin/miracle` и следуйте подсказке установщика.

Можно сначала скачать и прочитать скрипт:

```sh
curl -fL -o install.sh https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh
sh install.sh
```

## Windows через WSL 2

Нужен установленный WSL 2 с дистрибутивом GNU/Linux x64 или ARM64, например Ubuntu. Если он ещё не настроен, используйте [инструкцию Microsoft по установке WSL](https://learn.microsoft.com/en-us/windows/wsl/install). Затем откройте терминал своего Linux-дистрибутива.

Выполните в нём ту же установку:

```sh
curl -fsSL https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh | sh
~/.local/bin/miracle
```

Установщик выберет Linux-архив по архитектуре WSL. Все команды `miracle` выполняйте в этом же дистрибутиве. Держите программу и рабочую область в домашнем каталоге Linux, например `~/.local/share/miracle`; для `MIRACLE_INSTALL_ROOT` и `--data-dir` также выбирайте Linux-пути, а не `/mnt/c`. Это соответствует [рекомендации Microsoft для файлов Linux-приложений](https://learn.microsoft.com/en-us/windows/wsl/filesystems).

Команда напечатает `http://127.0.0.1:3001` или адрес выбранного порта. Откройте его вручную в браузере Windows. [WSL поддерживает доступ из Windows к локальному Linux-сервису](https://learn.microsoft.com/en-us/windows/wsl/networking). Используйте адрес как напечатано: Miracle проверяет Host, поэтому подмена `127.0.0.1` на имя компьютера или другой адрес не подходит.

## Первый запуск

`miracle` или `miracle open` запускает сервис в фоне и печатает `http://127.0.0.1:3001`. На macOS/Linux команда также открывает браузер; если он не открылся, перейдите по ссылке из терминала. В WSL откройте напечатанный адрес в браузере Windows. Аккаунт создавать не нужно: добавьте своё подключение в «Подключениях».

Если источник использует корпоративный CA, в настройках подключения выберите его PEM-файл. [Trino HTTPS](trino-connections.md) поддерживается с 0.2.1; [ClickHouse HTTPS](clickhouse-connections.md) также поддерживает клиентские сертификаты. Сертификат сохраняется с рабочей областью и переживает обновления приложения.

Источник в той же среде, где запущен Miracle, доступен через `127.0.0.1` и его порт. В WSL это адрес Linux-среды. Для источника, запущенного на стороне Windows, адрес зависит от режима сети WSL: в обычном NAT нужен адрес хоста Windows; подробности — в [документации Microsoft о сети WSL](https://learn.microsoft.com/en-us/windows/wsl/networking). Демонстрационные серверы и данные не устанавливаются.

| Команда | Действие |
| --- | --- |
| miracle / miracle open | Запустить и открыть браузер |
| miracle start | Запустить в фоне |
| miracle stop | Завершить запросы и остановить |
| miracle status | Проверить состояние |
| miracle serve | Запустить в текущем терминале |
| miracle --help / --version | Справка / версия |

Другой порт: `miracle start --port 3002`. Если порт занят, выберите свободный. Сервис слушает только loopback; две копии не могут открыть одну базу одновременно.

## Файлы

| ОС | Каталог приложения |
| --- | --- |
| macOS | ~/Library/Application Support/Miracle |
| Linux, включая WSL 2 | ${XDG_DATA_HOME:-~/.local/share}/miracle |

Код находится в `versions/`, рабочая область — в `data/`. В ней хранятся `miracle.sqlite` и `encryption.key`. Для отдельной рабочей области используйте `--data-dir PATH` или `MIRACLE_DATA_DIR` с каждой командой.

Ключ создаётся один раз. При потере или подмене ключа существующей базы запуск прекращается: восстановите исходную пару из копии.

## Резервное копирование и восстановление

Остановите сервис и создайте новую папку копии:

```sh
miracle stop
miracle backup ./miracle-backup
miracle start
```

Копия — каталог с согласованным снимком SQLite, ключом и описанием формата. При необходимости заархивируйте его обычным архиватором. Храните приватно: ключ позволяет расшифровать пароли источников.

Восстановление в новую пустую рабочую область:

```sh
miracle restore ./miracle-backup --data-dir ./restored-workspace
miracle open --data-dir ./restored-workspace
```

Непустая рабочая область не перезаписывается. Не копируйте один SQLite-файл у работающего сервиса: часть данных может находиться в WAL. Черновики браузера в копию не входят — сохраните запросы в каталог или скачайте .sql.

## Обновление и удаление

Остановите сервис, создайте копию и повторите установку нового релиза. Установщик сохраняет данные и активирует версию после проверки и распаковки. Старые файлы программы не заменяют резервную копию. Не открывайте более новую схему старой версией приложения.

Удаление: сначала `miracle stop`, затем сохраните копию вне каталога приложения. Удаление всего каталога удаляет и данные; удаление только launcher или отдельной версии — нет.

0.2.0 создаёт новую рабочую область. PostgreSQL-данные старой версии не импортируются и не удаляются.

Для ручной/offline установки скачайте `.tar.gz` нужной платформы, соседний `.sha256` и `install.sh` из одного релиза. Для WSL выбирайте Linux x64 или ARM64. Задайте `MIRACLE_ARCHIVE` равным пути к архиву. `MIRACLE_INSTALL_ROOT` и `MIRACLE_BIN_DIR` позволяют выбрать каталоги установки; их следует сохранять при последующих обновлениях.
