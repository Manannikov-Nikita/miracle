# Установка Miracle на свой компьютер

[← Обзор](../README.md) · [Руководство](usage.md)

Miracle — локальный сервис для одного человека. Готовая сборка содержит runtime; PostgreSQL, Docker, Node.js, npm и Git устанавливать не нужно. Codex CLI и Claude CLI для работы агентов устанавливаются отдельно.

**Инструкция для 0.8.1 и последующих выпусков.** Установщик `latest` загружает последний стабильный опубликованный выпуск. Для обновления установленной программы используйте `miracle update`.

## macOS и Linux

Нужны настольный браузер, curl и стандартные средства распаковки/проверки SHA-256. Поддерживаются macOS на Apple Silicon (ARM64) и GNU/Linux x64/ARM64. Alpine/musl не поддерживается. Используйте архив, контрольную сумму и установщик из одного [GitHub Release](https://github.com/Manannikov-Nikita/miracle/releases).

```sh
curl -fsSL https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh | sh
```

Установка выполняется в домашний каталог без sudo. Установщик проверяет PATH и, если каталога команды в нём нет, предлагает добавить его в настройки вашей оболочки. Вопрос работает и при запуске через `curl | sh`: ответ читается из терминала. Без согласия файл настроек не меняется; нажатие Enter означает отказ. После согласия откройте новый терминал или выполните напечатанную команду в текущем окне: запущенный установщик не может изменить окружение родительского терминала.

Поддерживаются zsh, Bash, sh и fish. Для zsh учитывается `ZDOTDIR`, для fish — `XDG_CONFIG_HOME`. При повторной установке одинаковая запись не добавляется. В режиме `auto`, если каталог уже присутствует в PATH, вопрос не появляется. Явное `MIRACLE_MODIFY_PATH=yes` сохраняет настройку и в этом случае.

Скрипт можно сначала скачать и прочитать:

```sh
curl -fL -o install.sh https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh
sh install.sh
```

Для автоматизированной установки настройку можно задать явно:

```sh
MIRACLE_MODIFY_PATH=yes sh install.sh  # добавить каталог в настройки оболочки
MIRACLE_MODIFY_PATH=no sh install.sh   # оставить настройки без изменений
```

По умолчанию используется `MIRACLE_MODIFY_PATH=auto`: в CI или без доступного терминала установщик не ждёт ответа и не меняет настройки. При нестандартном каталоге launcher укажите прежний `MIRACLE_BIN_DIR`; добавляется именно этот каталог.

## Если терминал пишет `miracle: command not found`

Эта ошибка означает, что оболочка не находит команду в PATH. При стандартной установке проверьте программу по полному пути:

```sh
~/.local/bin/miracle --version
~/.local/bin/miracle start
# Когда нужно остановить проект — из той же папки:
~/.local/bin/miracle stop
```

Если по полному пути команда работает, переустановка программы не обязательна. В zsh, Bash или sh добавьте каталог для **текущего терминала**:

```sh
export PATH="$HOME/.local/bin:$PATH"
miracle --version
```

Чтобы настройка сохранялась в новых терминалах, запустите актуальный установщик с явным согласием. Это работает и после временного `export PATH` выше, когда каталог уже виден текущему терминалу:

```sh
curl -fL -o install.sh https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh
MIRACLE_MODIFY_PATH=yes sh install.sh
```

Другой вариант — открыть новый терминал, в котором каталог ещё отсутствует в PATH, повторить обычную установку и ответить на вопрос. Для ручной настройки выберите вашу оболочку (`echo "$SHELL"`) и выполните соответствующий вариант один раз.

**zsh**, стандартная оболочка современного macOS:

```sh
printf '\nexport PATH="$HOME/.local/bin:$PATH"\n' >> "${ZDOTDIR:-$HOME}/.zshrc"
```

**Bash**, распространённая оболочка Linux и WSL:

```sh
printf '\nexport PATH="$HOME/.local/bin:$PATH"\n' >> "$HOME/.bashrc"
```

Если Bash открывается как login shell, он читает первый существующий файл из `~/.bash_profile`, `~/.bash_login`, `~/.profile`. Добавьте в этот файл такую же строку `export PATH="$HOME/.local/bin:$PATH"`, если он ещё не подключает `~/.bashrc`; если ни одного файла нет, создайте `~/.bash_profile` с этой строкой. Установщик учитывает оба режима Bash автоматически.

**sh:** добавьте строку в профиль входа:

```sh
printf '\nexport PATH="$HOME/.local/bin:$PATH"\n' >> "$HOME/.profile"
```

**fish:** выполните в fish; команда сохраняет настройку для следующих запусков:

```fish
fish_add_path "$HOME/.local/bin"
```

После ручного изменения файла откройте новый терминал и проверьте `miracle --version`. Обычный файл настройки не запускается автоматически в уже открытом окне; для него используйте команду добавления PATH выше.

При собственном `MIRACLE_BIN_DIR` замените `$HOME/.local/bin` его фактическим значением во всех примерах. Если даже полный путь даёт `No such file or directory`, проверьте выбранный каталог установки или повторите установку. Настройка PATH не меняет папки проектов и их данные.

## Windows через WSL 2

Нужен WSL 2 с дистрибутивом GNU/Linux x64 или ARM64, например Ubuntu: [установка WSL](https://learn.microsoft.com/en-us/windows/wsl/install). Команды установки и все команды `miracle` выполняйте в терминале этого дистрибутива. Установщик выберет Linux-архив по архитектуре WSL.

Держите программу и проекты в домашнем каталоге Linux, например `~/projects/analysis`, а не в `/mnt/c`. Для `MIRACLE_INSTALL_ROOT` и `--data-dir` также выбирайте Linux-пути: [рекомендация Microsoft](https://learn.microsoft.com/en-us/windows/wsl/filesystems).

Откройте напечатанный Miracle адрес в браузере Windows: [сеть WSL](https://learn.microsoft.com/en-us/windows/wsl/networking). Используйте адрес точно как напечатано; Miracle проверяет Host и Origin. Команда не требует Linux-браузера. Нативная установка Windows не поддерживается.

## Проект и первый запуск

Запускайте Miracle из папки своего проекта:

```sh
mkdir -p ~/projects/analysis
cd ~/projects/analysis
~/.local/bin/miracle
```

Текущая папка становится проектом. Данные Miracle сохраняются в её `.miracle/`: подключения, сохранённые SQL, документы редактора, снимки, доски, профили агентов и чаты. Обычные файлы проекта остаются рядом с этой папкой. Добавьте `.miracle/` в `.gitignore`: в ней находятся база и ключ шифрования.

`miracle` или `miracle open` запускает сервис в фоне и печатает адрес `http://127.0.0.1:PORT`; свободный порт выбирает ОС. На macOS/Linux команда также открывает браузер; в WSL перейдите по адресу вручную. Аккаунт Miracle не нужен: добавьте источник в «Подключениях».

Повторный запуск для той же папки, включая путь через символическую ссылку, открывает работающий экземпляр. Разные проекты имеют отдельные процессы, порты и браузерные сессии. Для запуска из другого места задайте проект явно:

```sh
miracle open --project-dir ~/projects/analysis
miracle status --project-dir ~/projects/analysis
```

| Команда                        | Действие для выбранного проекта                 |
| ------------------------------ | ----------------------------------------------- |
| miracle / miracle open         | Запустить и открыть браузер                     |
| miracle start                  | Запустить в фоне                                |
| miracle stop                   | Остановить сервис, активные SQL и задачу агента |
| miracle status / status --json | Проверить состояние и фактический адрес         |
| miracle serve                  | Запустить в текущем терминале                   |
| miracle --help / --version     | Справка / версия                                |

`miracle update --check` проверяет наличие нового выпуска, `miracle update` обновляет всю установленную программу; эти команды не привязаны к выбранному проекту.

`--port 3002` или `PORT=3002` задаёт конкретный порт. Если он занят, запуск завершится ошибкой. Для смены порта работающего проекта сначала выполните `miracle stop`. На один каталог данных допускается только один процесс.

`--data-dir PATH` или `MIRACLE_DATA_DIR` меняет только место хранения; папкой проекта и рабочим каталогом агента остаётся текущая папка либо `--project-dir`. Повторяйте переопределение для `status`, `stop`, `backup` и `restore`. Другой проект не может присвоить себе каталог данных зарегистрированного экземпляра. Для одной папки проекта работает один сервис даже при разных `--data-dir`: перед сменой хранения остановите текущий экземпляр с его прежним `--data-dir`. Команды с несовпадающим каталогом данных, включая `status` и `stop`, сообщат о работающем экземпляре и потребуют указать его хранение.

Для HTTPS Miracle автоматически использует доверенные CA Node.js и операционной системы. Если корпоративный CA ещё не доверен в системе, его можно загрузить вручную в PEM в настройках источника. Ручной CA применяется только к этому подключению; удаление возвращает автоматический режим. Подробности: [Trino](trino-connections.md), [ClickHouse и mTLS](clickhouse-connections.md). Источник в той же среде доступен через `127.0.0.1` и свой порт. В WSL это Linux-среда со своим хранилищем CA; доступ к источнику Windows зависит от [режима сети WSL](https://learn.microsoft.com/en-us/windows/wsl/networking). Демонстрационные серверы не устанавливаются.

## Файлы программы и данные

| ОС                   | Глобальный каталог установки             |
| -------------------- | ---------------------------------------- |
| macOS                | ~/Library/Application Support/Miracle    |
| Linux, включая WSL 2 | ${XDG_DATA_HOME:-~/.local/share}/miracle |

Код находится в `versions/`. Приватный реестр экземпляров — в `run/`, отдельные журналы проектов — в `logs/`. Эти каталоги общие для установки; данные каждого проекта по умолчанию лежат в `PROJECT/.miracle/`.

В каталоге данных находятся `miracle.sqlite` и `encryption.key`. Ключ создаётся один раз. При потере или подмене ключа существующая база не переинициализируется: восстановите исходную пару из копии.

## Резервное копирование и восстановление

Команды работают с текущим проектом или `--project-dir`:

```sh
cd ~/projects/analysis
miracle stop
miracle backup ../analysis-backup
miracle start
```

Копия содержит согласованный снимок SQLite, ключ и манифест. В неё входят документы редактора, доски, результаты, профили и чаты. Обычные файлы проекта и домашние настройки/авторизация Codex или Claude не входят. Храните копию приватно: ключ позволяет расшифровать пароли источников и команды профилей.

Восстановление в новый проект с отсутствующей либо пустой `.miracle/`:

```sh
mkdir -p ~/projects/restored-analysis
miracle restore ~/projects/analysis-backup --project-dir ~/projects/restored-analysis
miracle open --project-dir ~/projects/restored-analysis
```

Непустой каталог не перезаписывается. Не копируйте один SQLite-файл работающего сервиса: часть данных может находиться в WAL. После переноса проверьте исполняемые команды профилей и подтвердите их локально перед запуском агента; разрешение запуска не переносится с копией.

## Обновление

Проверьте выпуск без установки:

```sh
miracle update --check
```

Перед обновлением сделайте копии нужных остановленных проектов, затем выполните:

```sh
miracle update
```

Команда доступна для активной установленной версии; запуск обновления из исходников не поддерживается. По умолчанию выбирается последний стабильный официальный выпуск: CLI скачивает и проверяет его, затем запускает установку. Для следующих выпусков используйте ту же команду; ручная переустановка не требуется. Параметр `--to X.Y.Z` выбирает конкретный опубликованный выпуск; понижение версии отклоняется. Собственные каталоги установки и launcher сохраняются.

Обновляется вся установленная программа. Установщик аутентифицирует и корректно останавливает все зарегистрированные проекты перед активацией кода. При невозможности проверить экземпляр он прекращает обновление. Исчезнувший каталог данных не создаётся заново ради проверки. После успешного обновления снова откройте нужные проекты командой `miracle open`.

Старые версии программы не заменяют копии данных. Не открывайте более новую схему старой версией приложения. Папки проектов и обычные файлы не перемещаются обновлением.

### Тестовые выпуски

Стабильная 0.11.1 добавляет поддержку beta-канала. Пользователям 0.11.0 достаточно сначала выполнить `miracle update`, затем явно выбрать тестовый выпуск:

```sh
miracle update --beta --check
miracle update --beta
```

Флаг действует только для текущей команды. Обычный `miracle update` продолжает выбирать стабильные версии. Можно указать конкретную бету: `miracle update --beta --to 0.12.0-beta.1`. Старшая версия не заменяется более ранней, включая номера бет; стабильный выпуск X.Y.Z считается новее X.Y.Z-beta.N.

Сам переход 0.11.0 → 0.11.1 не меняет схему базы: остаётся версия 8. DuckDB и датасеты доступны только после отдельного перехода на 0.12.0-beta.1. Перед первым открытием существующего проекта в этой бете сделайте `miracle backup`: она обновляет базу до схемы 9, и для возврата к 0.11.x понадобится копия, сделанная до запуска беты.

Для прямой установки беты нужен её собственный `install.sh` с флагом `--beta`; стабильный установщик не выбирает тестовые выпуски. [Бета 0.12.0-beta.1 и её команда установки](https://github.com/Manannikov-Nikita/miracle/releases/tag/v0.12.0-beta.1).

## Offline-установка и удаление

Скачайте `.tar.gz`, соседний `.sha256` и `install.sh` из одного релиза. Для локального кандидата используйте эти же три файла из каталога сборки. Например, для macOS Apple Silicon:

```sh
MIRACLE_ARCHIVE="$PWD/miracle-0.11.1-darwin-arm64.tar.gz" sh ./install.sh
```

SHA-256 проверяется до запуска установщика из архива. `MIRACLE_INSTALL_ROOT` и `MIRACLE_BIN_DIR` задают каталоги установки и launcher; сохраняйте их при последующих установках. Установщик и runtime входят в архив/комплект, системный Node.js не нужен.

Для удаления сначала остановите проекты. Удаление кода установки не удаляет их `.miracle/`. Удаление папки проекта вместе с `.miracle/` удаляет его данные. Сохраняйте копии вне удаляемых папок.
