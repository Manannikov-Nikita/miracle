# Установка Miracle на свой компьютер

[← Обзор](../README.md) · [Руководство](usage.md)

Miracle — локальный сервис для одного человека. Готовая сборка содержит runtime; PostgreSQL, Docker, Node.js, npm и Git устанавливать не нужно.

**Эта инструкция относится к готовящейся версии 0.2.0.** Адреса установщиков заработают после публикации соответствующего GitHub Release. Docker-комплект 0.1.0 этих файлов не содержит.

## macOS и Linux

Нужны браузер, curl и стандартные средства распаковки/проверки SHA-256. Сборки: macOS Intel/Apple Silicon и GNU/Linux x64/ARM64. Alpine/musl не поддерживается.

```sh
curl -fsSL https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh | sh
miracle
```

Установка выполняется в домашний каталог без sudo. Если команда ещё не найдена в PATH, используйте `~/.local/bin/miracle` и следуйте подсказке установщика.

Можно сначала скачать и прочитать скрипт:

```sh
curl -fL -o install.sh https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh
sh install.sh
```

## Windows

В PowerShell на Windows 10 (1809+) или Windows 11 x64; установщик распаковывает ZIP штатными средствами PowerShell:

```powershell
Invoke-WebRequest 'https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.ps1' -OutFile "$env:TEMP\miracle-install.ps1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\miracle-install.ps1"
```

Используйте полный путь к miracle.cmd, который выведет установщик, или откройте новый терминал после изменения PATH. Native Windows ARM пока не заявлен.

## Первый запуск

`miracle` или `miracle open` запускает сервис в фоне и открывает `http://127.0.0.1:3001`. Если браузер не открылся, перейдите по ссылке из терминала. Аккаунт создавать не нужно: добавьте своё подключение в «Подключениях».

Источник на том же компьютере доступен через `127.0.0.1` и его порт. `host.docker.internal` для native-приложения не нужен. Демонстрационные серверы и данные не устанавливаются.

| Команда | Действие |
| --- | --- |
| miracle / miracle open | Запустить и открыть браузер |
| miracle start | Запустить в фоне |
| miracle stop | Завершить запросы и остановить |
| miracle status | Проверить состояние |
| miracle serve | Запустить в текущем терминале |
| miracle --help / --version | Справка / версия |

Другой порт: `miracle start --port 3002`. Если порт занят, выберите свободный. Сервис слушает только loopback; две копии не могут открыть одну базу одновременно.

## Файлы

| ОС | Каталог приложения |
| --- | --- |
| macOS | ~/Library/Application Support/Miracle |
| Linux | ${XDG_DATA_HOME:-~/.local/share}/miracle |
| Windows | %LOCALAPPDATA%\Miracle |

Код находится в `versions/`, рабочая область — в `data/`. В ней хранятся `miracle.sqlite` и `encryption.key`. Для отдельной рабочей области используйте `--data-dir PATH` или `MIRACLE_DATA_DIR` с каждой командой.

Ключ создаётся один раз. При потере или подмене ключа существующей базы запуск прекращается: восстановите исходную пару из копии.

## Резервное копирование и восстановление

Остановите сервис и создайте новую папку копии:

```sh
miracle stop
miracle backup ./miracle-backup
miracle start
```

Копия — каталог с согласованным снимком SQLite, ключом и описанием формата. При необходимости заархивируйте его обычным архиватором. Храните приватно: ключ позволяет расшифровать пароли источников.

Восстановление в новую пустую рабочую область:

```sh
miracle restore ./miracle-backup --data-dir ./restored-workspace
miracle open --data-dir ./restored-workspace
```

Непустая рабочая область не перезаписывается. Не копируйте один SQLite-файл у работающего сервиса: часть данных может находиться в WAL. Черновики браузера в копию не входят — сохраните запросы в каталог или скачайте .sql.

## Обновление и удаление

Остановите сервис, создайте копию и повторите установку нового релиза. Установщик сохраняет данные и активирует версию после проверки и распаковки. Старые файлы программы не заменяют резервную копию. Не открывайте более новую схему старой версией приложения.

Удаление: сначала `miracle stop`, затем сохраните копию вне каталога приложения. Удаление всего каталога удаляет и данные; удаление только launcher или отдельной версии — нет.

0.2.0 создаёт новую рабочую область. PostgreSQL-данные старой версии не импортируются и не удаляются.

Для ручной/offline установки скачайте архив нужной платформы, соседний .sha256 и установщик из одного релиза. Задайте `MIRACLE_ARCHIVE` равным пути к архиву. `MIRACLE_INSTALL_ROOT` и `MIRACLE_BIN_DIR` позволяют выбрать каталоги установки; их следует сохранять при последующих обновлениях.
