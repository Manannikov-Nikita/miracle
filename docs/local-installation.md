# Установка Miracle на свой компьютер

[← Обзор](../README.md) · [Руководство](usage.md)

Miracle — локальный сервис для одного человека. Готовая сборка содержит runtime; PostgreSQL, Docker, Node.js, npm и Git устанавливать не нужно. Codex CLI и Claude CLI для работы агентов устанавливаются отдельно.

**Подготовка 0.3.0:** проекты, агенты и команда обновления ниже входят в готовящийся выпуск. Публичный установщик пока устанавливает 0.2.1. В 0.2.0 и 0.2.1 данные находятся в общем каталоге установки `data/`, порт по умолчанию — 3001. Для перехода используйте [отдельную инструкцию обновления](#обновление-с-020-и-021).

## macOS и Linux

Нужны настольный браузер, curl и стандартные средства распаковки/проверки SHA-256. Сборки: macOS Intel/Apple Silicon и GNU/Linux x64/ARM64. Alpine/musl не поддерживается. Используйте архив, контрольную сумму и установщик из одного [GitHub Release](https://github.com/Manannikov-Nikita/miracle/releases).

```sh
curl -fsSL https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh | sh
```

Установка выполняется в домашний каталог без sudo. Если команда ещё не найдена в PATH, используйте `~/.local/bin/miracle` и следуйте подсказке установщика. Скрипт можно сначала скачать и прочитать:

```sh
curl -fL -o install.sh https://github.com/Manannikov-Nikita/miracle/releases/latest/download/install.sh
sh install.sh
```

## Windows через WSL 2

Нужен WSL 2 с дистрибутивом GNU/Linux x64 или ARM64, например Ubuntu: [установка WSL](https://learn.microsoft.com/en-us/windows/wsl/install). Команды установки и все команды `miracle` выполняйте в терминале этого дистрибутива. Установщик выберет Linux-архив по архитектуре WSL.

Держите программу и проекты в домашнем каталоге Linux, например `~/projects/analysis`, а не в `/mnt/c`. Для `MIRACLE_INSTALL_ROOT` и `--data-dir` также выбирайте Linux-пути: [рекомендация Microsoft](https://learn.microsoft.com/en-us/windows/wsl/filesystems).

Откройте напечатанный Miracle адрес в браузере Windows: [сеть WSL](https://learn.microsoft.com/en-us/windows/wsl/networking). Используйте адрес точно как напечатано; Miracle проверяет Host и Origin. Команда не требует Linux-браузера. Нативная установка Windows не поддерживается.

## Проект и первый запуск

Запускайте Miracle из папки своего проекта:

```sh
mkdir -p ~/projects/analysis
cd ~/projects/analysis
~/.local/bin/miracle
```

Текущая папка становится проектом. Данные Miracle сохраняются в её `.miracle/`: подключения, сохранённые SQL, документы редактора, снимки, доски, профили агентов и чаты. Обычные файлы проекта остаются рядом с этой папкой. Добавьте `.miracle/` в `.gitignore`: в ней находятся база и ключ шифрования.

`miracle` или `miracle open` запускает сервис в фоне и печатает адрес `http://127.0.0.1:PORT`; свободный порт выбирает ОС. На macOS/Linux команда также открывает браузер; в WSL перейдите по адресу вручную. Аккаунт Miracle не нужен: добавьте источник в «Подключениях».

Повторный запуск для той же папки, включая путь через символическую ссылку, открывает работающий экземпляр. Разные проекты имеют отдельные процессы, порты и браузерные сессии. Для запуска из другого места задайте проект явно:

```sh
miracle open --project-dir ~/projects/analysis
miracle status --project-dir ~/projects/analysis
```

| Команда                        | Действие для выбранного проекта                 |
| ------------------------------ | ----------------------------------------------- |
| miracle / miracle open         | Запустить и открыть браузер                     |
| miracle start                  | Запустить в фоне                                |
| miracle stop                   | Остановить сервис, активные SQL и задачу агента |
| miracle status / status --json | Проверить состояние и фактический адрес         |
| miracle serve                  | Запустить в текущем терминале                   |
| miracle --help / --version     | Справка / версия                                |

`miracle update --check` проверяет наличие нового выпуска, `miracle update` обновляет всю установленную программу; эти команды не привязаны к выбранному проекту. Они доступны начиная с 0.3.0.

`--port 3002` или `PORT=3002` задаёт конкретный порт. Если он занят, запуск завершится ошибкой. Для смены порта работающего проекта сначала выполните `miracle stop`. На один каталог данных допускается только один процесс.

`--data-dir PATH` или `MIRACLE_DATA_DIR` меняет только место хранения; папкой проекта и рабочим каталогом агента остаётся текущая папка либо `--project-dir`. Повторяйте переопределение для `status`, `stop`, `backup` и `restore`. Другой проект не может присвоить себе каталог данных зарегистрированного экземпляра. Для одной папки проекта работает один сервис даже при разных `--data-dir`: перед сменой хранения остановите текущий экземпляр с его прежним `--data-dir`. Команды с несовпадающим каталогом данных, включая `status` и `stop`, сообщат о работающем экземпляре и потребуют указать его хранение.

Для корпоративного HTTPS загрузите PEM CA в настройках источника. Подробности: [Trino](trino-connections.md), [ClickHouse и mTLS](clickhouse-connections.md). Источник в той же среде доступен через `127.0.0.1` и свой порт. В WSL это Linux-среда; доступ к источнику Windows зависит от [режима сети WSL](https://learn.microsoft.com/en-us/windows/wsl/networking). Демонстрационные серверы не устанавливаются.

## Файлы программы и данные

| ОС                   | Глобальный каталог установки             |
| -------------------- | ---------------------------------------- |
| macOS                | ~/Library/Application Support/Miracle    |
| Linux, включая WSL 2 | ${XDG_DATA_HOME:-~/.local/share}/miracle |

Код находится в `versions/`. Приватный реестр экземпляров — в `run/`, отдельные журналы проектов — в `logs/`. Эти каталоги общие для установки; данные каждого проекта по умолчанию лежат в `PROJECT/.miracle/`. Старый общий `data/` автоматически не переносится.

В каталоге данных находятся `miracle.sqlite` и `encryption.key`. Ключ создаётся один раз. При потере или подмене ключа существующая база не переинициализируется: восстановите исходную пару из копии.

## Резервное копирование и восстановление

Команды работают с текущим проектом или `--project-dir`:

```sh
cd ~/projects/analysis
miracle stop
miracle backup ../analysis-backup
miracle start
```

Копия содержит согласованный снимок SQLite, ключ и манифест. В неё входят документы редактора, доски, результаты, профили и чаты. Обычные файлы проекта и домашние настройки/авторизация Codex или Claude не входят. Храните копию приватно: ключ позволяет расшифровать пароли источников и команды профилей.

Восстановление в новый проект с отсутствующей либо пустой `.miracle/`:

```sh
mkdir -p ~/projects/restored-analysis
miracle restore ~/projects/analysis-backup --project-dir ~/projects/restored-analysis
miracle open --project-dir ~/projects/restored-analysis
```

Непустой каталог не перезаписывается. Не копируйте один SQLite-файл работающего сервиса: часть данных может находиться в WAL. После переноса проверьте исполняемые команды профилей и подтвердите их локально перед запуском агента; разрешение запуска не переносится с копией.

## Обновление с 0.2.0 и 0.2.1

В этих версиях нет команды `miracle update`. Первый переход выполняется повторным запуском нового установщика. Команды установки 0.3.0 в этом разделе станут доступны **после публикации выпуска**; до этого используйте архив кандидата и offline-установку ниже.

Перед обновлением запишите адрес старой рабочей области из браузера и `miracle status --json`. Сохранённые запросы и доски уже находятся в SQLite, но несохранённые SQL-вкладки 0.2.x находятся только в браузере. Скачайте важные черновики как `.sql`, затем остановите старую версию и сделайте копию:

```sh
~/.local/bin/miracle status --json
~/.local/bin/miracle stop
~/.local/bin/miracle backup "$HOME/miracle-before-0.3.0"
```

Если раньше использовали `--data-dir`, повторите его во всех трёх командах. Каталог для копии должен быть новым или пустым. Эта копия сохраняет базу и ключ до миграции; браузерные черновики в неё пока не входят.

После публикации 0.3.0:

```sh
curl -fL -o install-miracle-0.3.0.sh \
  https://github.com/Manannikov-Nikita/miracle/releases/download/v0.3.0/install.sh
sh install-miracle-0.3.0.sh
~/.local/bin/miracle --version
```

При нестандартной установке сохраните те же `MIRACLE_INSTALL_ROOT` и `MIRACLE_BIN_DIR`, что использовали ранее. Например:

```sh
MIRACLE_INSTALL_ROOT="$HOME/apps/Miracle" \
MIRACLE_BIN_DIR="$HOME/bin" \
sh install-miracle-0.3.0.sh
```

Новый установщик проверяет и корректно останавливает зарегистрированные экземпляры перед сменой версии. Он сохраняет базы и ключи на месте и выводит подсказку для открытия обнаруженной прежней рабочей области. Если сервис был остановлен и использовал нестандартный порт, возьмите порт из сохранённого адреса: установщик не может восстановить браузерную историю.

После установки **сначала откройте прежние данные на прежнем адресе**, как описано ниже. Обычный запуск 0.3.0 из новой папки создаёт отдельную `.miracle/`; пустая новая область не означает, что старые данные удалены.

## Перенос существующей рабочей области

SQL-черновики 0.2.x доступны только на исходном origin: том же протоколе, адресе и порту, в том же браузере и профиле. Не очищайте данные сайта до завершения импорта.

Выберите папку проекта и из неё откройте старые данные новой версией. Пример для стандартной установки macOS и старого адреса `http://127.0.0.1:3001`:

```sh
mkdir -p ~/projects/analysis
cd ~/projects/analysis
miracle open --data-dir "$HOME/Library/Application Support/Miracle/data" --port 3001
```

На Linux/WSL прежний каталог обычно `${XDG_DATA_HOME:-$HOME/.local/share}/miracle/data`. Для собственного `MIRACLE_INSTALL_ROOT` это его `data/`, если вы не задавали отдельный `--data-dir`. Укажите фактические старые каталог и порт. Остановленный глобальный каталог автоматически не перемещается.

Дождитесь загрузки и импорта SQL-вкладок в серверные документы; проверьте их текст. Смена порта или браузерного профиля не даёт доступа к прежним черновикам. При первом открытии SQLite автоматически мигрирует со старой схемы на новую; подключения, ключ, сохранённые запросы, результаты и доски остаются в этой же базе.

Теперь из той же папки проекта остановите экземпляр и перенесите данные через новую копию. В неё уже войдут импортированные SQL-черновики:

```sh
miracle stop --data-dir "$HOME/Library/Application Support/Miracle/data"
miracle backup ~/miracle-migrated-backup --data-dir "$HOME/Library/Application Support/Miracle/data"
miracle restore ~/miracle-migrated-backup --project-dir ~/projects/analysis
miracle open --project-dir ~/projects/analysis
```

Для восстановления `.miracle/` должна отсутствовать или быть пустой. Сохраняйте старый каталог и обе копии до проверки нового проекта. Для возврата к старой версии используйте **копию до миграции**, восстановленную в отдельный пустой каталог: открывать обновлённую базу кодом 0.2.x нельзя. PostgreSQL-данные версии 0.1.0 автоматически не импортируются и не удаляются.

## Обновление установленной 0.3.0 и последующих версий

Проверьте выпуск без установки:

```sh
miracle update --check
```

Перед обновлением сделайте копии нужных остановленных проектов, затем выполните:

```sh
miracle update
```

Команда доступна для активной установленной версии; запуск обновления из исходников не поддерживается. По умолчанию выбирается последний стабильный официальный выпуск. Параметр `--to X.Y.Z` выбирает конкретный опубликованный выпуск; понижение версии отклоняется. Собственные каталоги установки и launcher сохраняются.

Обновляется вся установленная программа. Установщик аутентифицирует и корректно останавливает все зарегистрированные проекты перед активацией кода. При невозможности проверить экземпляр он прекращает обновление. Исчезнувший каталог данных не создаётся заново ради проверки. После успешного обновления снова откройте нужные проекты командой `miracle open`.

Старые версии программы не заменяют копии данных. Не открывайте более новую схему старой версией приложения. Папки проектов и обычные файлы не перемещаются обновлением.

## Offline-установка и удаление

Скачайте `.tar.gz`, соседний `.sha256` и `install.sh` из одного релиза. Для локального кандидата используйте эти же три файла из каталога сборки. Например, для macOS Apple Silicon:

```sh
MIRACLE_ARCHIVE="$PWD/miracle-0.3.0-darwin-arm64.tar.gz" sh ./install.sh
```

SHA-256 проверяется до запуска установщика из архива. `MIRACLE_INSTALL_ROOT` и `MIRACLE_BIN_DIR` задают каталоги установки и launcher; сохраняйте их при последующих установках. Установщик и runtime входят в архив/комплект, системный Node.js не нужен.

Для удаления сначала остановите проекты. Удаление кода установки не удаляет их `.miracle/`. Удаление папки проекта вместе с `.miracle/` удаляет его данные. Сохраняйте копии вне удаляемых папок.
