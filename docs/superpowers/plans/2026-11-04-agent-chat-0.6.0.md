# Agent chat 0.6.0 implementation plan

**Goal:** Deliver image references, a persistent auto-approve toggle and a compact transcript on a running local test stand.

**Architecture:** Extend existing React/Fastify/SQLite and native Codex/Claude transports. Keep image input separate from text/context; store metadata in messages. Save approval policy per chat on the server.

**Spec:** `docs/superpowers/specs/2026-11-04-agent-chat-0.6.0-design.md`

## Tasks and ownership

- [x] Image backend: validate and persist image inputs, serve authenticated image URLs, pass real multimodal input to both providers. Test limits, malformed input, image-only messages and protocol transport.
- [x] Approval backend: default-off `AgentChat.autoApprove`, POST/PATCH chat API, manual/automatic transitions and persisted approval decisions. Test switching while waiting, concurrent requests and disabling.
- [x] Frontend input: file picker/paste/drop, removable previews, per-chat drafts and retry identity; wire image payload and auto-approve toggle. Test image-only send, retry retention and draft isolation.
- [x] Transcript: move approvals below model replies, compact default-closed details and visible decision buttons; keep activity muted. Test ordering and absence of approval-triggered scrolling.
- [x] Integration: independent review, appropriate full tests/build, real browser and native CLI smoke where available. Leave a persistent local stand and record its address.

## Review focus

Image read finishing after switching chats; retry after a lost POST response; malformed or oversized images before persistence; approval mode changes during pending requests; refresh/reconnect consistency; image retention through backup and provider session recovery.

## Delivery constraints

No published release, merge or production deployment. Work on the 0.6.0 candidate branch. Preserve existing user projects; use an isolated test project for browser QA.
