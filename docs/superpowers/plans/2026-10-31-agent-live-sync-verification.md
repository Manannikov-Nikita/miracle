# Синхронизация изменений локального агента

Дата: 31 октября 2026. Проверка на ПК, стенд `http://127.0.0.1:50264/`, проект `.local/demo-project`.

## Причины и исправления

- Сохранённый запрос обновлялся отдельно от открытого документа. Теперь изменение запроса в одной транзакции обновляет связанные редакторы, если их SQL и источник не расходятся с прежней версией запроса. Ревизии и события сохраняются вместе; пользовательские черновики не перезаписываются.
- При сравнении источников учитываются унаследованные настройки подключения: отсутствие `database`, `catalog` или `schema` в редакторе совместимо с тем же значением, явно сохранённым в запросе. Явные пустые значения и реально отличающиеся источники не объединяются.
- Редактор принимал независимые изменения за конфликт. Добавлено слияние относительно общей сохранённой версии: например, локальное переименование совместимо с новым SQL агента. SQL и контекст источника считаются связанными полями. Реальные пересекающиеся правки сохраняются для разрешения пользователем.
- Ручное сохранение сначала синхронизирует документ, затем читает свежие SQL и ревизию исходной вкладки. Пришедшее во время ожидания обновление агента не заменяется устаревшей копией; переключение вкладки не меняет цель сохранения.
- Доска сравнивала объекты с учётом порядка ключей JSON; подтверждение собственного сохранения могло прийти после более свежего события. Сравнение стало каноническим, обработка ревизий и резервных черновиков учитывает порядок событий. Локальное перемещение камеры совместимо с изменением содержимого агентом.
- Поток событий закрывался при заполнении буфера ответа. Теперь доставка приостанавливается до `drain`, затем продолжается с последовательного курсора журнала. Повторы отсекаются, очередь ограничена, зависшие соединения очищаются.

## Автоматическая проверка

Итоговая сборка: `npm test` — 765 тестов, 62 файла, успешно; `npm run build` — успешно, включая оба TypeScript-проекта; `git diff --check` — успешно. Сохраняется прежнее предупреждение Vite о размере основного bundle.

Поведенческие регрессии покрывают перестановку ключей, события до HTTP-ответа, поздний ответ 409, возврат агента к ранее сохранённому содержимому, изменение камеры, независимые и пересекающиеся правки редактора, перенос контекста источника, распространение сохранённого запроса, атомарный откат и повтор команды. Отдельные тесты проверяют реальный Node Writable с обратным давлением, порядок replay/live и очистку соединения.

## Проверка настоящим Codex CLI

Использован настроенный профиль Codex local (`0.165.0-alpha.1.2`). На стенде созданы отдельные проверочные запрос, документ и доска; исходная NYC-доска не редактировалась. Сервер обновлён при отсутствии выполняющейся задачи.

В новом разговоре агент через MCP:

1. Изменил `sync-check.sql` с `SELECT 1 AS sync_check;` на `SELECT 42 AS sync_check;` только через сохранение запроса, без `edit_editor`.
2. Изменил текст существующей заметки на «Обновлено агентом без перезагрузки» и переместил её в `(90, 80)`.
3. Перечитал сохранённый редактор и доску, подтвердив результат.

Открытый SQL-редактор показал `SELECT 42` ещё до завершения задачи, без перезагрузки страницы. Заметка также обновилась через поток событий; при открытии доски отображались новый текст и статус «Сохранено», без предупреждений о конфликте. Серверная проверка подтвердила ревизию запроса 2, редактора 3 и доски 2. Ход завершился, активной задачи нет. SQL не выполнялся.

В реальном Monaco проверены Undo и Redo: агентская правка отменяется до `SELECT 1` и возвращается к `SELECT 42`. Исходная NYC-доска также открывается со статусом «Сохранено», без конфликта черновика.

После установки итоговой сборки проверено обычное сохранение `sync-check.sql` через диалог: сохранение завершилось, диалог закрылся, SQL остался `SELECT 42`, ошибки об изменении запроса в другой вкладке нет.
