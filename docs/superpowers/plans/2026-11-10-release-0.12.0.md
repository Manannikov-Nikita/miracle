# Miracle 0.12.0 — DuckDB and named datasets

Implementation of the user-approved plan. SQLite remains authoritative; local DuckDB execution runs in child processes. Existing 0.11.0 documents remain compatible.

## Global constraints

- Project-wide case-insensitive editable SQL names, separate from board titles.
- Datasets expose complete raw result snapshots, survive board deletion, and refresh all linked current nodes atomically. Consumers pin versions. No automatic dependency refresh.
- CSV/TSV, Parquet, JSON/JSONL and XLSX with sheet selection; no XLS, network files, globs or computed paths.
- Local sources use `{ kind: 'local', sql }`; legacy remote sources remain valid.
- SQLite stores dataset metadata and existing result chunks; DuckDB is disposable. Backup/restore retains datasets.
- Native engine and Excel ship offline for macOS arm64, Linux arm64 and Linux x64. Preserve current execution/output limits. DuckDB memory 512 MiB, staged inputs plus spill 2 GiB per run.
- Desktop UI verification only. Do not publish this release. Preserve unrelated source checkout changes.

## Interface agreement

- Shared `Dataset`: id, name, revision, resultSetId, source, columns, createdAt, updatedAt. Columns extend existing Column with sourceName and duckdbType.
- WorkspaceOperations: listDatasets(), dataset(id), registerDataset(input), renameDataset(id,input), deleteDataset(id,input), commitDatasetRefresh(id,input). Inputs use baseRevision/mutationId where applicable.
- POST /api/datasets registers {resultSetId,name?,boardId?,nodeId?,baseRevision?,mutationId?}; GET /api/datasets and /:id; PATCH /:id {name,baseRevision,mutationId?}; DELETE /:id {baseRevision,mutationId?}; POST /:id/refresh {baseRevision,source?,mutationId?} starts ordinary query run and returns QueryRun.
- Dataset node fields: datasetId, datasetRevision, datasetName. New result nodes request registration with publishDataset:true, optional datasetName; absent flag on old nodes means no implicit migration.
- Local executor will expose executeLocalQuery(input) returning existing engine output; root and executor implementer finalize detailed TypeScript interface before integration.

## Acceptance

Remote result → named board dataset → join project file → new dataset → restart works through both UI and MCP. Shared refresh is transactional; old board saves cannot roll data back. Full raw snapshots are scanned beyond UI page/output limits. Offline installed XLSX works; unsupported native architectures remain unclaimed unless tested in CI.
