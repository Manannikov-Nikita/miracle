# Проверка программируемых графиков

Дата: 2026-11-01. Ветка: `codex/custom-agent-charts`; исходная версия `68844bd`. Изменения реализованы локально, без публикации релиза.

## Реализованный сценарий

Сохранённый SQL-результат поддерживает `view: "custom"` и версионированный исходник HTML/CSS/JavaScript. Код исполняется в iframe с отдельным origin; родитель передаёт только столбцы, строки, размер и тему. Встроенный агент получает контракт через `custom_chart_guide`, сохраняет композицию через `board_patch`, читает диагностику через `read_custom_chart_status`. Отчёты привязаны к актуальному исходнику и снимку, имеют срок действия и защиту от повторного применения старой последовательности.

Два синтетических примера воспроизводят классы композиций из запроса: положительные/отрицательные столбцы с выносками, скобкой и сноской; горизонтальный waterfall с соединителями и составным итогом. Они содержат настоящую привязку к строкам, обработку пустого результата, перестановки столбцов, точных числовых строк и кнопки с доступом с клавиатуры.

## Автоматические проверки

Использован Node 24.22.2. Интеграционные тесты запускались с разрешёнными loopback-портами: ограниченный sandbox выдавал `listen EPERM`, что отдельно воспроизведено на исходной версии. Исходная версия: 91 файл, 1117 тестов, все проходят.

Финальный полный прогон на `ee86387`: 100 файлов, 1180 тестов, все проходят (27,73 с). `npm run build` включает оба TypeScript-проекта, Vite и серверную сборку; проходит. Существующее предупреждение Vite о размере общего bundle остаётся информационным.

Проверены строгая схема и UTF-8-лимиты, атомарное отклонение слишком большой доски, лимиты полного снимка, отсутствие метаданных подключения в данных iframe, CSRF/auth маршрутов, MCP-пагинация, смена хеша и снимка, несколько вкладок, TTL, последовательности, переполнение реестра, жизненный цикл iframe, ошибки загрузки/инициализации, очистка и сохранение исходника при переключении вида.

Фиксированное ожидание 180 мс в компонентном тесте заменено управляемым продвижением debounce и ограниченным ожиданием наблюдаемого состояния: React `act` и асинхронный WebCrypto не завершались в прежнем фиксированном интервале под полной нагрузкой.

## Проверка в настоящем браузере

Использовалась production-сборка, Chrome и Playwright. `tests/custom-chart-browser-server.mjs` создаёт отдельный временный проект с локальным синтетическим SQL-движком; реальные пользовательские данные не открываются. Сценарий находится в `tests/custom-chart-browser-smoke.js`.

Финальный сценарий прошёл все 12 проверок. Подтверждены отрисовка двух примеров и статус `rendered`; физический клик и Space внутри графика; изменение размера; переключение таблица/кастомный график с сохранением исходника; ошибки выполнения, диагностика, таблица и повтор; сохранение после перезагрузки; независимость графика от ошибки табличного preview; ошибка полного снимка и восстановление; обычный график ECharts; обновление SQL-снимка с сохранением исходника и подтверждением `rendered`; диагностика синтаксической ошибки.

Проверки доступа к родительскому DOM и localStorage получают `SecurityError`. Fetch к API и внешнему адресу блокируется CSP. Внешние script/img, включая script с прежним nonce, блокируются до сетевого запроса; перехватчик запросов зафиксировал ноль внешних обращений. Это не утверждение о гарантированной изоляции CPU или всех возможных исходящих каналов обычного iframe.

При локальном обновлении снимка браузер начинает новую отрисовку до завершения автосохранения доски. Сервер корректно отклоняет ранний отчёт для ещё не сохранённого снимка; следующий heartbeat через 20 секунд повторяет его для актуального состояния. Браузерная проверка ожидает этот цикл, не объявляя `not_observed` успехом.

Playwright неправильно учитывал transform доски для координат внутри iframe. Проверка переводит локальные координаты кнопки через фактический масштаб iframe и отправляет настоящий mouse click; DOM `.click()` не используется как замена физической проверке.

## Реальный встроенный CLI: проверка заблокирована окружением

Codex CLI 0.136.0 запускается через production-адаптер Miracle, но модельный запрос не начинается:

- текущая конфигурация содержит неподдерживаемое этой версией значение reasoning `ultra`;
- временный тестовый профиль с совместимым reasoning получает отказ: выбранной модели требуется более новый CLI;
- собственный `model/list` установленного CLI возвращает default-модель, которую backend аккаунта отклоняет как недоступную.

Новая сессия с обнаруженным default не устранила отказ. Более новый executable в проверенных стандартных путях Codex.app отсутствует. Глобальная конфигурация, установленный CLI и пользовательские профили не изменялись; дополнительный перебор моделей не выполнялся.

Все попытки остановились до Miracle MCP-вызовов. Поэтому создание и последующая правка графика настоящим провайдером **не подтверждены**; тестовая доска осталась исходной. Автоматические проверки инструментов и браузера не подменяют эту проверку. Повторить после устранения совместимости CLI/модели/аккаунта. Claude CLI в окружении отсутствовал.

## Ревью и принятые решения

Независимо проверены контракт, сервер и клиент; затем выполнено ревью всей ветки. Выявленные ошибки исправлены: reusable nonce разрешал внешние скрипты; ошибка табличного preview препятствовала запуску диагностики; удаление watermark при TTL/переполнении позволяло старому отчёту ожить; кнопка возврата к графику исчезала при ошибке таблицы. Дополнительная браузерная проверка выявила несогласованное значение отсутствующего `sourceRevision`: клиент теперь использует серверное значение `0`, а изменение источника по-прежнему повышает его до `1`. Регрессионные тесты подтверждают обновление с сохранением кода и отклонение позднего результата после изменения SQL или удаления блока. Итоговое ревью исправлений до `ee86387`: замечаний не осталось.

MCP выдаёт подробности страницами по 10, максимум 20, сохраняя общий статус по всем текущим наблюдениям. При заполнении реестра новые ключи отклоняются вместо вытеснения действующих; timestamp и последовательность фиксируются при создании отчёта. Допустимый сдвиг часов ограничен пятью секундами.

Работа велась в отдельной ветке исходного checkout: системный Git не проходил проверку лицензии Xcode, native worktree не распознал репозиторий, рабочий CLT Git позволил изолировать изменения веткой. Параллельные исполнители имели раздельные области файлов. Обычный iframe принят согласно согласованному решению; гарантированный отдельный процесс/CPU-квота и полный запрет всех исходящих каналов не входят в эту версию.

## Воспроизведение

```sh
npm run build
node tests/custom-chart-browser-server.mjs
# Открыть origin, напечатанный временным сервером, в Playwright CLI:
playwright-cli open http://127.0.0.1:PORT
playwright-cli run-code --filename tests/custom-chart-browser-smoke.js
```

Сценарий изменяет только именованную временную доску и восстанавливает её документ в `finally`; повторный запуск допустим. Тестовый сервер завершать через Ctrl-C. Node24 требуется для fixture-файла TypeScript. Оба временных сервера и браузерные сессии, использованные в этой проверке, закрыты по окончании.
