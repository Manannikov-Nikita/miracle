# Miracle 0.5.1 Implementation Plan

> **For agentic workers:** Use the task ownership below; verify each independent change and review the combined branch before PR creation.

**Goal:** Prepare 0.5.1 through a PR with board-title, connection-authentication and agent-command fixes.

**Architecture:** Keep current React/Fastify/native CLI architecture. Make board updates idempotent, add an explicit memory-only Trino login lifecycle, and parse wrapper launch prefixes independently from provider arguments.

**Tech Stack:** TypeScript, React, Fastify, SQLite, Node.js, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-04-release-0.5.1-design.md`

## Global constraints

- No user project data, credentials or provider homes in fixtures.
- No shell execution for agent profile commands; FULL TLS validation for Trino.
- PR targets main; do not publish or merge the candidate.

## Review focus

- Board event before/after HTTP response, with later revision and identical names on different IDs.
- Browser auth cancellation and reconnect, draft save/edit and token expiry.
- Token server origins and URLs, TLS trust, bounded responses, absence of secret DTO/log output.
- Wrapper flags versus provider flags, quoted Unicode/spaces and unsupported grammar.
- Production build, existing Basic Auth/CA connections and existing provider commands remain functional.

## Follow-up: context-aware SQL completion

Extend the existing local completion engine with a small tolerant tokenizer and SELECT-scope analysis. A full validating SQL parser would be brittle while a query is being typed; regex-only projection extraction would confuse nested calls, strings and subqueries. No query execution or extra metadata requests are needed.

- [x] Pin regressions for SELECT-derived GROUP BY suggestions, dialect-specific aliases, aggregate/window exclusion, completed keys, prefix filtering and nested query scopes.
- [x] Analyze the cursor's SELECT block and clause, preserving expressions and quoted names while isolating other statements/subqueries.
- [x] Prioritize selected dimensions for GROUP BY, output expressions for ORDER BY, columns for expression clauses and sources for FROM/JOIN; retain metadata fallback.
- [x] Check bounded suggestion lists, actual Monaco insertion, existing SQL tests, build and independent review.
- Keep the candidate in the existing draft; do not publish or merge the release.
