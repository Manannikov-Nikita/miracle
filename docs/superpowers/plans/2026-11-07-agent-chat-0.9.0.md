# Agent Chat 0.9.0 Implementation Plan

> **For agentic workers:** Execute independent file scopes in parallel; root integrates, verifies and reviews the complete change. Use test-driven-development for behavior and record verification below. No publication or changes to production installations.

**Goal:** Add SQL activity rings, answerable agent questions, subagent status and no-stop steering to the existing chat.

**Architecture:** Preserve the existing 480 px chat and add a 56 px activity rail without collapse. Persist server-owned SQL attribution and normalize provider interaction events; the client renders the authoritative state and sends answers/steers to the existing process.

**Tech Stack:** Existing React, TypeScript, Fastify, SQLite, provider JSON protocols, Vitest.

**Spec:** ../specs/2026-11-07-agent-chat-0.9.0-design.md

## Global constraints

- Existing project data, approvals, cancellation and idempotent mutations stay intact.
- No fake progress or inferred child-agent status; unknown data stays unknown.
- No-stop steering must never call cancel or start a replacement process.
- Keep inputs retryable and stale responses isolated to their chat/turn.
- Node 24 from .local/node24; use /Library/Developer/CommandLineTools/usr/bin/git because system git invokes an unaccepted Xcode license.

## Review focus

- Turn completion racing with steer acceptance must not lose or duplicate an accepted message.
- Answer retries and concurrent answers must resolve the right native request once; autoapprove must not fabricate answers.
- Child notifications must not finish the parent or mix child assistant text into the parent transcript.
- SQL outlives agent turns, pauses and restarts; manual SQL must not be counted.
- Client chat switches/reconnects must not display stale activity or discard drafts.
