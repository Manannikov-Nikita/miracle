# Miracle 0.5.1

Подготовить кандидат через PR в `main`; публикация тега и слияние не входят в эту работу. Последний опубликованный выпуск остаётся 0.5.0.

## Поведение

- Создание/сохранение доски не дублирует её название при любом порядке HTTP-ответа и `board.updated`. Список уникален по ID, более новая ревизия не заменяется старой.
- В форме подключения можно показать и снова скрыть введённый пароль. Сохранённые секреты не возвращаются из API.
- Trino принимает импорт JDBC URL с `SSL=true`, `SSLVerification=FULL`, `externalAuthentication=true`, `externalAuthenticationTokenCache=MEMORY`; каталог и схема извлекаются из пути. Неизвестные или неподдерживаемые параметры вызывают явную ошибку.
- Внешняя авторизация Trino выполняется отдельным действием через браузер и polling, не занимая 15-секундный запрос метаданных. Токены хранятся только в памяти процесса, изолированы между проектами и подключениями, не попадают в DTO, БД, журналы или резервные копии. TLS всегда проверяется, пользовательский CA поддерживается.
- Отмена, истечение времени, смена подключения и закрытие формы прекращают ожидающий вход. Смена настроек/удаление подключения и отказ токена инвалидируют связанное состояние.
- Кастомные команды агентов сохраняют поддерживаемые параметры CLI и корректный префикс запуска через известные wrapper-команды. Shell не используется; неподдерживаемые конструкции объясняются пользователю.
- Сравнение с ORCA отделяет подтверждённые ошибки запуска от отдельной архитектурной возможности нативных терминалов. Переход на PTY/ACP не входит в патч-релиз.

## Проверки

Регрессии на реальных клиентских компонентах, subprocess-фикстуры агентов, локальный HTTPS Trino/OAuth стенд, тесты отмены/изоляции/редактирования, TypeScript и сборка. Корпоративный адрес пользователя не используется как тестовый сервер. Реальный корпоративный IdP и реальные CLI проверяются отдельно от фикстур.
