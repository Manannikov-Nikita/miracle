# Работа агента с отдельными объектами

Пользователь видит, с каким объектом работает агент, и временно не может его изменять. По явному решению пользователя блокируются только затронутые блоки доски; остальные блоки остаются редактируемыми.

## Решения

- Сервер хранит эксклюзивные claims на SQL-документ, сохранённый запрос, файл проекта, блок/связь доски или её метаданные. Блокировка метаданных не блокирует все блоки. Связанные SQL-документы и сохранённые запросы защищаются совместно.
- Агент явно вызывает `begin_entity_work` до чтения объекта для изменения; `end_entity_work` освобождает законченную часть. Мутации автоматически захватывают свой точный набор объектов как страховку. Чтение контекста и активная вкладка сами по себе ничего не блокируют.
- Claims живут до освобождения или окончания задачи. Отмена/ошибка/перезапуск освобождают их; отложенная мутация старой задачи не может записать данные после отмены. Состояние доступно через `GET /api/agent-work` и события `agent.work`.
- Сохраняется глобальная версия доски для порядка событий; независимые изменения объединяются по ID узлов и связей через трёхстороннее слияние. База серверного слияния берётся из сохранённых событий `board.updated`, а не из неподтверждённого клиентского снимка. Настоящее конкурирующее изменение одного объекта не затирается.
- Клиент объединяет входящие события, ответ сохранения и свои несохранённые изменения. Undo/redo меняет только объекты собственного перехода и сохраняет чужие новые изменения. Уже существующие локальные черновики сохраняются при получении блокировки и не отправляются поверх изменений агента.
- По уточнению пользователя анимированный фиолетово-синий градиент применяется только к верхней вкладке редактора. Остальные области без цветовой подсветки и рамок; индикатор «Агент работает» нейтральный и неподвижный. Без мигания и перекрытия содержимого; reduced-motion отключает движение градиента. Чтение, выделение, копирование и навигация доступны.
- Файлы, изменяемые нативными инструментами CLI, требуют явного claim до файловой операции. Сервер защищает редактор Miracle, но не может запрещать записи произвольного внешнего текстового редактора.

## Рассмотренные варианты

Блокировка всей доски проще, но пользователь выбрал блокировку отдельных блоков. Чисто визуальная блокировка недостаточна из-за автосохранения и нескольких браузерных вкладок. Выбран серверный контроль владения с объединением независимых изменений.

## Проверки

Разные блоки сохраняются одновременно; один блок защищён сервером и интерфейсом. Проверяются связанные запросы, отмена во время await, SSE до HTTP-ответа, переподключение, undo/redo, удаление соседнего узла со связями, незавершённые черновики и освобождение после завершения. Browser проверяет видимую подсветку, доступность соседнего блока и восстановление редактирования.
