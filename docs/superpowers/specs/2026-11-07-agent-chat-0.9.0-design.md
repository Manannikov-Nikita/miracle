# Чат агента: подготовка 0.9.0

Пользователь запросил четыре связанные функции: активные SQL и прогресс запуска по датам, ответы на вопросы, сведения о саб-агентах и дополнительные сообщения без остановки работы. Выбран компактный виджет: счётчик и кольца постоянно, подробности по нажатию.

## Поведение

- Слева от нынешней панели добавляется полоса шириной 56 px без сворачивания. Сверху вниз: саб-агенты, значок базы со счётчиком SQL, кольца запросов. Постоянно видны только иконки, числовые счётчики и прогресс. Переписка и поле ввода сохраняют существующую ширину 480 px на ПК. На узком окне полоса превращается в компактную строку.
- Виджет считает только SQL, запущенные агентом выбранного чата через Miracle; обычный запрос или последовательный пакет дат считается одним запуском. Кольца показывают только running/cancelling: у каждого активного пакета есть прогресс completed / total, обычные активные запросы показывают неопределённое вращение. Приостановленные пакеты остаются в подробностях и отслеживаются для продолжения, но не занимают активные кольца. Пауза, ошибка и завершение различимы текстом. Reduced motion отключает вращение.
- Подробности показывают SQL с подсветкой синтаксиса, состояние, прогресс, текущую дату и попытку. Кнопка «Открыть в редакторе» открывает исходный запуск вместе с подключением и диапазоном дат, сохраняет черновики и не запускает запрос повторно. Чат продолжает отслеживать SQL после окончания ответа агента. Ручные запросы и интроспекция схемы не попадают в счётчик.
- Структурированный вопрос показывается в переписке с вариантами ответа, множественным выбором там, где это разрешено, и своим текстом. Ответ отправляется ожидающему агенту; автоапрув не отвечает за пользователя. Завершённые/прерванные вопросы остаются в истории без активной формы.
- Саб-агенты показывают имя/идентификатор, задачу и фактический статус по событиям провайдера. Подробности доступны из виджета. Их сообщения и завершения не завершают и не подменяют основной ответ.
- Одна кнопка composer переключается по содержимому ввода: при активной задаче и пустом поле — квадрат «Стоп»; при тексте или изображении — стрелка отправки, которая передаёт Steer в текущий чат. При отсутствии активной задачи пустая кнопка отправки выключена. Горячая клавиша отправки никогда не останавливает работу. Повтор запроса после сетевой ошибки не дублирует ввод. Ошибка сохраняет черновик. Контекст и вложения сохраняют существующие правила.
- Codex использует native turn/steer и item/tool/requestUserInput. Claude использует потоковый ввод без interrupt и нативные вопросы; неподдерживаемые возможности должны сообщаться честно, без остановки и перезапуска как имитации Steer.

## Подход

Выбрана узкая полоса состояния и раскрываемые подробности. Постоянный список всех SQL и саб-агентов занял бы значительную часть рабочего пространства; пользователь предпочёл компактный вариант. Состояние SQL берётся из сохранённых запусков с серверной привязкой к чату, а не из текста агента. События провайдеров нормализуются в типизированные вопросы и статусы саб-агентов.

## Ограничения и проверки

Существующие данные, профили, разрешения и отмена сохраняются. Стенд 3078 обновляется после проверок. Публикация релиза и изменение версии не входят в этот шаг. Реальный Claude отсутствует: протокол проверяется подпроцессными фикстурами; это ограничение должно быть отражено в результате. Проверяем смену чата, переподключение, перезапуск, гонки окончания и Steer, повторные ответы, чужие/устаревшие вопросы и SQL, завершение дочернего агента, клавиатуру и сохранение ширины переписки.
