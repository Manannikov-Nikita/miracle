# Trino HTTPS с корпоративным CA

Пользователь установленного Miracle 0.2.0 не может проверить Trino HTTPS: Node возвращает `fetch failed`, а у Trino нет поля доверенного CA. Ручная правка launcher с NODE_EXTRA_CA_CERTS теряется при переустановке. Требуется поддержка CA в продукте, по существующему образцу ClickHouse.

## Подход

CA на уровне подключения выбран как решение из переданного описания: PEM загружается в форме, валидируется до сохранения, шифруется SecretBox в SQLite и применяется только к этому источнику. Глобальный NODE_EXTRA_CA_CERTS остаётся документированной альтернативой для администратора. Автоматическое доверие всем системным CA и правка launcher не требуются для решения.

TrinoOptions: `tls?: { caCert?: string | null } | null`; ConnectionInput получает optional nullable `trino`. Публичный DTO содержит только `trino.tls.hasCaCert`. Отсутствующее поле сохраняет CA, null удаляет. Не добавляются клиентские сертификаты/mTLS и параметры отключения TLS.

## Ограничения

- PEM-цепочка до 128 КиБ, каждый сертификат проверяется X509Certificate; CA разрешён только с HTTPS.
- CA зашифрован в новом поле `trino_options_encrypted`; SQLite schema 2→3, совместимость миграции и backup/restore со схемами 1 и 2.
- Отдельный undici.Agent с connect.ca и обязательной проверкой сервера/имени; без CA остаётся обычное доверие Node, включая его переменные окружения.
- POST запроса, GET страниц, DELETE отмены, метаданные и выгрузки по датам используют CA. DELETE после завершения/ошибки основного запроса остаётся работоспособным; диспетчеры закрываются.
- Ошибки TLS различают недоверенный CA, имя сервера и срок действия, не раскрывая сертификат, пароль или детали внутреннего соединения.
- UI показывает выбранный/сохранённый CA, позволяет заменить/удалить, блокирует проверку и сохранение во время чтения файла; позднее чтение не меняет другую форму.
- Нет корпоративных сертификатов, ключей, адресов и аккаунтов в исходниках, тестах или релизе. Только синтетические TLS fixtures.

## Проверка

Реальные HTTPS-тесты должны подтвердить отказ без CA/с чужим CA/неверным именем, успех с нужным CA, страницы и отмену, изоляцию источников. API проверяет зашифрованное хранение и merge/delete, UI — загрузку и сохранение формы. Native smoke проверяет CA через установленный архив и после backup/restore. Общий набор и сборка должны пройти; существующий HTTP/ClickHouse функционал сохраняется.
