# Проводник проекта — кандидат 0.6.0

Пользователь попросил заменить раздел SQL-файлов проводником проекта, сохранив SQL-режим для `.sql`, а остальные текстовые файлы открывать с подсветкой. Редактирование и сохранение явно подтверждены.

- Раздел «Проводник проекта» показывает реальные папки и файлы текущего проекта. Папки загружаются при раскрытии; поиск работает по имени и относительному пути. Старые сохранённые в БД SQL-запросы доступны отдельной группой «Сохранённые SQL» без миграции пользовательских данных.
- Вкладки имеют идентичность по пути. Повторное открытие фокусирует существующий черновик, чистую вкладку обновляет с диска. `.sql` сохраняет запуск запросов и результаты, остальные файлы используют Monaco с определением языка по имени и расширению.
- Сохранение кнопкой или Cmd/Ctrl+S пишет исходный файл с проверкой SHA-256 ревизии. Конфликт оставляет черновик; доступны скачивание черновика и явная загрузка дисковой версии. Закрытие изменённой вкладки предлагает сохранить/отбросить/отменить.
- Черновики восстанавливаются из browser storage; при его недоступности интерфейс сообщает об этом. Обычный текстовый файл не публикует контекст скрытого SQL-редактора агенту.
- API: GET `/api/project/tree?path=`, GET/PUT `/api/project/file?path=`; тело PUT `{content,baseRevision}`. Существующий поиск @ссылок сохраняется.
- Открываются текстовые UTF-8 файлы до 2 МиБ. SQL дополнительно ограничен существующим лимитом документа редактора в 1 млн символов. Для бинарных/слишком больших файлов показывается понятная ошибка. Служебное хранилище, Git, зависимости/сборки и symlink недоступны в проводнике.

Переименование, удаление файлов и предпросмотр бинарных форматов не входят в этот шаг. Проверка: API/rooted paths/conflicts, смешанные вкладки и drafts, дерево/search/keyboard, полный набор тестов, сборка, реальные изменения тестовых файлов через стенд 3060.

## Создание файлов — уточнение пользователя

В выбранной директории можно создать пустой файл через «+» и поле имени прямо в дереве. Расширение задаёт пользователь в имени, отдельного окна выбора формата нет. Enter/галочка создаёт и открывает файл, Escape отменяет ввод. При выбранном файле используется его родительская папка; заголовок «ФАЙЛЫ ПРОЕКТА» выбирает корень. POST `/api/project/file` принимает `{directory,name}`, возвращает ProjectTextFile со статусом201. Эксклюзивное создание исключает перезапись совпадающего имени, проверяются границы проекта и допустимость имени. Если пользователь переключился на другой файл пока запрос выполнялся, успешный ответ не меняет его новую активную вкладку.

## Живой Markdown-редактор файлов

По уточнению пользователя `.md`/`.markdown` открываются в том же CodeMirror live-preview, что используется в Markdown-блоке доски, с оформлением документа и раскрытием исходника активной строки. `ProjectTextEditor` выбирает MarkdownEditor по языку файла, остальные языки продолжают использовать Monaco. Общий компонент получает необязательные onSave/onCursorChange/ariaLabel/maxLength; прежние вызовы доски сохраняют поведение и лимит200к символов, файлы используют лимит текстового файла. Редактор пересоздаётся для другого file.id, чтобы история отмены не переносила содержимое между файлами. Сохранение, конфликты и восстановление черновиков используют общий файловый путь.
