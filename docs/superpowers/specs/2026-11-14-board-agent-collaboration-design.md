# Работа агентов с доской

Пользователь хочет точное понимание взаимного расположения объектов, быстрые изменения, преимущественное делегирование простых независимых задач и отдельный цвет каждого исполнителя без конфликтов и разрастания контекста. Подтверждено: текущий профиль/модель, не более двух исполнителей одновременно.

## Подход

Выбраны управляемые приложением реальные процессы через существующий adapter. Нативные субагенты провайдера наследуют один MCP token, поэтому их наблюдаемые события не дают независимого владения. Передача self-reported workerId также недостаточна. Каждый управляемый исполнитель получает собственный capability, неизменяемую область записи и новую сессию без истории родителя.

Остаёмся в текущем worktree и стеке TypeScript/React/Node24; без новых зависимостей и миграции документа доски. Выпуск релиза не входит в эту задачу.

## Пространственные данные и операции

Чистая геометрия переносится в shared и используется одинаково UI и сервером. `read_board_scene` возвращает ограниченные по размеру элементы: ID, короткое название, видимые границы, поворот, соединения/концы линий и связи относительно запрошенных объектов. Никаких SQL, полных текстов, таблиц или исходников графиков по умолчанию. Страницы привязаны к ревизии. Слайды имеют отдельные системы координат.

`read_board_items` читает конкретные узлы/связи с явным ограничением и постраничным JSON для больших объектов. `board_spatial` выполняет move/place/align/distribute/resize атомарно и возвращает короткую квитанцию с изменённой геометрией. Пространственная операция требует точной текущей ревизии, включая read-зависимости якорей; повтор mutationId возвращает прежний результат. Старый board_patch сохраняется и получает режим компактного ответа; отдельные настройки редактируются через него.

## Исполнители

`delegate_board_task` принимает краткую задачу, boardId, точные nodeIds/edgeIds, имя и mutationId. До запуска приложение резервирует объекты и зависимые связи. Независимые задачи идут параллельно, пересечения ожидают освобождения; родитель не может писать поверх дочерних claims. Не более 2 процессов и 16 задач за ход; предел длительности отдельной простой задачи — 180 секунд. Эти ограничения — решения реализации, не отдельные пожелания пользователя.

`board_task_status` даёт ограниченный статус/итог (ожидание не более 10 секунд), `cancel_board_task` отменяет одного исполнителя. Повтор делегирования не запускает второй процесс. Worker не может делегировать, обращаться к другому проекту/доске, запускать SQL или менять источники. Записи проверяют scope в EntityWork, включая автоматические claims. Чтение сцены своей доски разрешено, полное содержимое доступно только назначенных объектов.

AgentEntityWork получает optional worker `{id,name,color}` с серверным индексом палитры 0..15. Owner сравнивается по worker.id, при его отсутствии по turnId. releaseOwner освобождает одного исполнителя; releaseTurn — всю задачу. При отмене capability отзывается сразу, блокировки снимаются только после остановки процесса и завершения операций. Старые события совместимы.

Дочерние session/context-usage не меняют сессию и метрику родителя. В родительский контекст возвращаются только краткие итоги; сообщения, approvals и lifecycle правильно атрибутируются. Root завершает/останавливает оставшихся детей до освобождения общих locks. Нативные потомки worker не считаются отдельными владельцами.

Область записи и запрет доступа к остальным данным проекта проверяются на сервере Miracle MCP. Существующий доверенный CLI-профиль остаётся границей доверия для запуска процесса. Для Claude список встроенных инструментов ограничен вопросами, а MCP наследуется только из переданной конфигурации. Для Codex отключены shell, unified exec, нативные исполнители и поиск, используется файловый режим read-only. Настроенные пользователем внешние MCP Codex и поведение произвольного wrapper определяются профилем; выделенная область Miracle не является отдельной песочницей ОС.

## Интерфейс и контекст

Используется существующая единственная граница блока/геометрии. Цвет берётся из server-issued worker metadata, рядом доступно имя; без второй рамки и изменения hitbox. Цвета уникальны в рамках 16 задач хода; основной агент сохраняет прежний вид. Учитываются линии, фигуры, текст, карточки, изображения и презентации, reduced motion и клавиатурное выделение.

Selected boardEdges передаются вместе с boardNodes: сбор, фиксация до flush, dismiss, retry, история, серверная проверка и канонические подписи. Не подменять удалённую/чужую стрелку другой. Начальный prompt содержит ID/счётчики и указание пользоваться сценой, не копирует полное содержимое выбранных графиков и первые 100 объектов.

## Проверка

TDD для новых контрактов, целевые unit/integration проверки каждого блока, затем весь suite и production build. Нужны проверки вращений/наконечников, равных видимых промежутков, сохранения якоря, атомарности, exact revision и idempotency; межвладельческих конфликтов, scope и cancellation через await; двух реальных тестовых CLI-процессов через HTTP MCP, очереди пересечений и повторного делегирования; правильного цвета и selected edges; ограниченного размера scene/items/status/prompt. Desktop проверка на отдельном временном проекте, без изменения пользовательской доски. Реальные платные вызовы провайдера не требуются для протокольных тестов и не заявляются как проверенные.
