# Эксплуатация Miracle

Miracle — личный локальный сервис с SQLite и внешними источниками ClickHouse/Trino. Проектные каталоги и агенты ниже описывают текущую исходную версию; опубликованная 0.2.1 ещё использует общий каталог данных. [Установка и переход](local-installation.md).

## Экземпляры проектов

Текущая папка запуска задаёт проект, `--project-dir PATH` выбирает его из другого места. Проект по умолчанию хранит данные в `.miracle/`. `--data-dir PATH` и `MIRACLE_DATA_DIR` переопределяют только хранение. Для всех команд управления повторяйте те же параметры проекта и хранения.

CLI слушает только `127.0.0.1` и выбирает свободный порт ОС, если не задан `--port` или `PORT`. `miracle status --json` возвращает фактический адрес. Повторное открытие проекта использует тот же процесс; символические ссылки разрешаются в канонический путь. У разных проектов отдельные процессы, порты, сессии и журналы. Для одного каталога данных допускается только один процесс; занятое хранилище не перепривязывается к другой папке проекта. Одна папка проекта также допускает только один сервис независимо от переопределения хранения. Если запущен экземпляр с другим `--data-dir`, команды явно отклоняют несовпадение: используйте прежний параметр для `status`/`stop` и остановите сервис перед сменой хранения.

Проверки Host, Origin, сессии и CSRF защищают локальные данные; браузерные cookies разделяются по портам. Используйте точный напечатанный адрес. Публичное размещение через reverse proxy не поддерживается.

`miracle start` запускает фоновой процесс, `miracle serve` оставляет его в текущем терминале. `miracle stop` аутентифицирует конкретный экземпляр и ждёт остановки HTTP и освобождения SQLite; сохранённый PID не даёт права завершать чужой процесс. Автозапуск при входе в ОС не устанавливается.

## Данные и агенты

В `.miracle/` находятся `miracle.sqlite` и `encryption.key`: подключения, SQL-документы, снимки, доски, профили, чаты, события и сведения о задачах агента. Пароли источников, приватные TLS-материалы и команды профилей шифруются. Ключ проверяется при запуске; существующая база с отсутствующим или неверным ключом не переинициализируется. Не помещайте `.miracle/`, копии, токены и личные данные в Git или публичные журналы.

Процесс удерживает исключительную блокировку SQLite до завершения работы. Миграции транзакционны и отклоняют неподдерживаемую более новую схему. SQL-документы и доски используют ревизии; конфликт не должен заменять несохранённый браузерный текст. Изменения агента поступают через поток событий и восстанавливаются после переподключения.

В одном проекте одновременно работает одна задача агента. Браузер можно закрыть: задача продолжится в серверном процессе. Кнопка остановки в чате завершает задачу; остановка сервиса завершает и его дочерний CLI. После сбоя незавершённые SQL и задачи агентов отмечаются прерванными без автоматического повтора инструментов.

Codex CLI и Claude CLI устанавливаются и авторизуются отдельно штатными средствами провайдера. Miracle не хранит учётную запись провайдера. Команда профиля определяет модель и разрешения; нативный CLI получает папку проекта как cwd и читает её инструкции. Область инструментов файлов и shell определяется выбранным CLI и его разрешениями. Локальный MCP Miracle даёт доступ к контексту, SQL и доскам этого проекта; пароли подключений остаются на сервере. Путь проекта является рабочим каталогом, а не дополнительной файловой песочницей.

Чат сохраняет выбранный профиль и провайдера. При доступной нативной сессии диалог продолжается в ней; если сессия недоступна, новая получает сохранённый разговор с явным уведомлением, без воспроизведения старых действий. После переноса/восстановления профили требуют локальной проверки и подтверждения команды. Подробнее: [руководство по агентам](usage.md#локальные-агенты).

## Лимиты

По умолчанию: 120 секунд, 50 000 строк или 20 MiB на SQL-запрос, два одновременных SQL-запуска и 2 GiB на результаты. Один агентный ход — отдельное ограничение проекта. Снимки без ссылок с досок удаляются через 24 часа, завершённая история SQL — через 30 дней. Снимки на досках остаются; неудачное обновление сохраняет предыдущие данные.

## Резервные копии и обновление

Остановите выбранный проект перед `miracle backup DIRECTORY`. Команда сохраняет согласованный SQLite, ключ и манифест. Документы, доски, результаты и чаты входят в копию. Обычные файлы проекта, файлы домашнего каталога и нативная авторизация/настройки провайдера в неё не входят. Сохраните их отдельно при необходимости. Ключ в копии позволяет расшифровать приватные данные источников и команды профилей.

`miracle restore DIRECTORY --project-dir NEW_PROJECT` требует существующую папку проекта и отсутствующую либо пустую `.miracle/`. Можно задать отдельный `--data-dir`. Исходная копия сохраняется; проверьте восстановление до удаления старых данных. Не копируйте только файл работающей базы: часть данных может находиться в WAL.

Прежде чем переносить старую глобальную рабочую область, откройте её на исходном браузерном origin и дождитесь импорта старых SQL-черновиков. Затем остановите сервис и используйте backup/restore с явным старым `--data-dir`: [пошаговый перенос](local-installation.md#перенос-существующей-рабочей-области). Автоматического перемещения глобального `data/` нет.

Новый установщик проверяет все записи приватного реестра и аутентифицированно останавливает работающие проекты перед активацией версии. Неизвестный ответ или чужой сервис на сохранённом порту останавливает обновление; чужие PID не завершаются. Удалённое/перемещённое хранилище не создаётся при проверке. Код находится в глобальном `versions/`, реестр в `run/`, журналы по проектам в `logs/`; данные по умолчанию находятся в папках проектов. Старые файлы кода не заменяют резервные копии. Не удаляйте ключ шифрования ради исправления ошибки запуска.

## Windows через WSL 2

Установка и команды выполняются внутри GNU/Linux WSL 2. Программу и проекты храните в файловой системе Linux, например `~/projects/analysis`, а не `/mnt/c`: [рекомендация Microsoft](https://learn.microsoft.com/en-us/windows/wsl/filesystems). В браузере Windows откройте адрес, напечатанный командой. При проблеме проверьте `miracle status` в том же дистрибутиве. Подробнее: [установка](local-installation.md#windows-через-wsl-2), [сеть WSL](https://learn.microsoft.com/en-us/windows/wsl/networking).

## Разработка и источники

См. [CONTRIBUTING.md](../CONTRIBUTING.md). API-тесты используют временные SQLite-каталоги, протоколы агентов — subprocess-фикстуры. Реальный CLI smoke проверяется отдельно; наличие адаптера не означает подтверждённую совместимость со всеми версиями Codex или Claude.

Используйте отдельного пользователя аналитического источника с правами чтения. Проверка SQL в Miracle дополняет ограничения базы. Источник в той же среде доступен по `127.0.0.1`; в WSL это Linux. Доступ к серверу Windows зависит от [режима сети](https://learn.microsoft.com/en-us/windows/wsl/networking). [.env.example](../.env.example) содержит параметры разработки; для Vite сохраняется API-порт 3001 и `APP_ORIGIN` интерфейса.
