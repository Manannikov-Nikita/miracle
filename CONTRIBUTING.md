## Локальный запуск

Нужны **Node.js 24**, npm и Docker с Compose v2. Следующие команды выполняются из корня репозитория:

```sh
npm ci
node scripts/init-local.mjs
docker compose --profile test up -d --wait postgres clickhouse trino
ENCRYPTION_KEY_FILE=.local/encryption.key COOKIE_SECURE=false npm run dev
```

Интерфейс: `http://127.0.0.1:5178`. API: порт `3001`. PostgreSQL: порт `5544`. Тестовые ClickHouse и Trino содержат синтетические данные. Первый администратор создаётся в отдельном терминале:

```sh
ENCRYPTION_KEY_FILE=.local/encryption.key npm run bootstrap-admin
```

CLI запросит данные администратора; не передавайте пароль в аргументах команды. Настройки окружения перечислены в [.env.example](.env.example), альтернативный запуск API и параметры тестовых подключений — в [operations.md](docs/operations.md#local-development).

Примеры выше используют синтаксис shell macOS/Linux. В PowerShell задавайте переменные окружения через `$env:ИМЯ = 'значение'` перед npm-командой.

Ключ `.local/encryption.key` создаётся один раз; повторный запуск скрипта сохраняет его. Он нужен для расшифровки секретов подключений. Сохраняйте ключ и данные при пересборках. Каталог `.local/`, `.env`, дампы, пароли, сертификаты и частные данные не должны попадать в коммиты.

## Проверки

```sh
npm test
npm run build
npm run test:integration
```

Интеграционные тесты требуют запущенный Compose-профиль `test`. Они создают отдельную временную БД и работают с настоящими ClickHouse и Trino. Проверяются роли, отмена запросов, точные типы, ограничения, страницы результатов, конфликты, обновление снимков, перезапуск и восстановление резервной копии.

Для изменения контейнера или поставки дополнительно выполните подходящие проверки из [инструкции выпуска](docs/releasing.md#локальная-приёмка-разработчиком). `scripts/smoke-image.sh` использует собранный `miracle-app:latest`, временную БД и не публикует порт. Изменения TLS проверяются `npx tsx tests/clickhouse-tls-integration.ts`.

Если меняются зависимости, обновите `package-lock.json` и выполните `npm run notices`; результат в `THIRD_PARTY_NOTICES.md` входит в поставку.

## Pull request

1. Опишите проблему и итоговое поведение. Ограничьте PR одной понятной задачей.
2. Добавьте проверку, которая подтверждает исправленный сценарий. Для правок текста достаточно проверки ссылок и команд.
3. Для UI приложите снимок с синтетическими данными; для поведения укажите шаги воспроизведения и проверки.
4. Выполните `git diff --check` и перечислите пройденные проверки в описании PR. Если часть проверок недоступна, укажите это явно.
5. Обновите документацию, если изменились установка, интерфейс или ограничения.

Не удаляйте постоянные Docker volumes ради прохождения проверки. Тестовые скрипты и инструменты восстановления должны работать только со своей изолированной средой.
